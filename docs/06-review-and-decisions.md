# 架构决策与待验证项

日期：2026-09-15。状态：当前决策记录。产品语义以01、02为准，架构以03为准。本页记录已采用的选择及理由，实施进度见13。

## 已确定的选择

| 决策 | 理由与范围 |
|---|---|
| 对外仅 Source、Experience、Playbook | 工作和效果记录作为内部视图；保留来源身份、会话及修订关联，减少独立对象和名称转换 |
| 围绕方法形成、使用和演进构建产品 | WorkView提供经历，Experience表达有范围的主张，Playbook组织做法，真实新结果继续学习 |
| 官方Hindsight与Agent模块作为实现起点 | 复用提取、因果链接、归纳、综合、索引、采集和回填，避免重复建设底层能力 |
| 第一阶段交付P0–P3，按官方能力拆分增量 | P0–P3作为内部关卡连续推进；原生结构化生成、存储、适合的UI组件及作业优先复用，工作包见[13](13-implementation-plan.md) |
| 保留独立产品核心和MemoryEngine边界 | 产品身份、方法步骤、用户控制与范围不依附原生ID；首期只做Hindsight |
| 官方工具分层使用 | 原生UI/CLI用于配置及诊断，官方直连作为隔离基线，产品操作经过核心 |
| L1–L5仅作可选分析框架 | 经验有用途、依据和范围即可结束提炼；发布与验收不要求层级标签或覆盖率 |
| 发布查询与学习候选分离 | 未发布原生事实不能挤占方法top-k；投影可重建，当前产品状态权威不转移 |
| 方法默认一次提供完整指导 | 工作Agent执行检查并选路，服务保留资格、权限和修订校验；不默认要求独立模型重评与完成证据解锁，生成修订阶段仍审查依据和路径 |
| Agent MCP收敛为三个工具 | getGuidance同时返回方法和经验，另有submitSource与feedback；核心组织检索与任务关联，减少Agent串联调用 |
| 方法准备只承诺可观察边界 | 注入和显式准备时核对当前资格；不维护分支执行会话，不能保证拦截内部思考 |
| Copilot以会话为采集单位 | 优先复用官方reader；学习来源只从transcript入库，保留全部已接收原文并用最近窗口学习，删除任务切分与重复工具回调采集 |
| 任务反馈直接保存当前事实 | 记录投递、任务结果和用户评价，删除步骤采用追踪、事件回放和独立使用关联；这些状态的维护成本不能换来可靠的效果归因 |
| 会话结果保留判断来源 | 回顾开启时按原始观察判断会话结果，用户可确认或纠正；结果不证明方法收益，处理材料与学习来源分别保存，见[11](11-post-release-evaluation.md) |
| 学习、推荐、回顾和通知独立 | 真结果可在授权内自动学习；周报与自评不制造新支持 |
| 首版导出Skill快照 | 提供可审阅方法产物，不建设自动Skill安装/执行平台 |
| 首版使用当前数据格式 | 产品仍在开发，没有旧用户数据；旧开发布局迁移不列为功能或发布前置条件，保留当前格式备份恢复与不兼容拒绝 |
| 多轮工作由宿主执行 | 页面负责方法管理、任务关联与状态反馈；复用官方采集和回填，补产品身份与版本检查，不另建页面执行器 |
| 单核心进程与本地单用户 | 降低部署和一致性成本，团队/跨设备及多后端以后按需设计 |
| 当前方法正文由 Hindsight 保存，写入前检查 | 不要求多版本恢复；产品保存控制、来源和确认记录，删除旧版正文管理。生成与审查继续使用既有原生作业，未切换长期 delta 路线 |
| 学习作业统一payload与原生处理 | 服务和存储直接使用同一payload，冻结输入以保证重试一致；生成/审查共用提交、恢复、轮询和取结果逻辑，保留各自发布规则 |

## 上游接入选择

P0前固定官方coding-agents或copilot-cli候选版本，依据实际事件、来源覆盖和改造范围选择复用模块。原生SDK和HTTP/MCP调用需要转换为产品语义，不承诺直接安装原插件或只换URL即可完成。

Hindsight配置和扩展留在适配器内，可执行原生提炼、请求过滤和入口控制，不能成为产品用户意图的唯一保存位置。原生生成型结果作为候选；不能限定有效依据的任务输出路径不开放。

官方能力依据集中在[复用核查](research/2026-09-14-agent-integration-reuse/README.md)，研究记录不等于产品可运行。产品定位不依赖宣称官方没有高层归纳、UI或CLI。

## P0必须解决的问题

| 待验证项 | 需要得到的结果 | 失败后的处理 |
|---|---|---|
| 宿主采集与方法回填 | 真实动作/结果样例、来源角色及能力覆盖 | 补实际接入模块或缩小支持声明，不能伪造观察 |
| 原生候选到产品方法 | 真实材料产生有依据的经验、方法步骤和来源绑定 | 调整mission/profile或补方法组装，不用标签完成验收 |
| 发布投影 | 前置资格过滤、暂停屏障、索引确认 | 使用独立可重建索引，不靠扩大top-k后筛 |
| 方法指导与反馈 | 完整分支和边界可读，Agent先诊断再选路，结果关联可核对 | 修正指导和宿主关联，不新增通用执行器 |
| 来源重处理与用户控制 | 原生ID变化不恢复已停用方法，错误绑定可检测 | 保持受影响对象暂停，补来源映射，不承诺任意改写识别 |
| 原文与长期依据保留 | 产品、原生副本和清理传播实际一致 | 明确调整保留profile或管线，不静默扩大保存 |
| Windows依赖及运行预算 | 固定组件可启动、后台独立、用量与取消可计量 | 先修切片或重审发行配置，不公布未通过支持 |

发布索引、方法生成和宿主接入已有局部运行证据，完整退出条件仍未全部通过。各项当前状态以[实现计划](13-implementation-plan.md)为准；本表保留需要验证的结果及失败处理方式。

## 配置和范围变更

更换引擎、源账号、知识范围或保留政策是显式配置变更。迁移前确认在途操作、原生和产品数据一致；恢复保留后来发生的纠正、停用和忘记。不能用恢复旧备份绕过用户意图。

扩展预算、改变接口或放宽安全/质量条件须在验收前修改相应合同及profile。未验证项不自动视为满足，无法兑现的承诺需先重审范围，不能在代码中隐式降级。

## 产品投入的判断

先完成一个主题的方法学习体验，再与合理配置的官方方案比较工作行为及成本。新增方法没有影响工作、方法维护成本高于收益时，先调整学习与使用方式；UI和记录数量不能抵充。

保留原生已满足部分，不为了维持设计规模另写一套。若最终只需要安装、配置和诊断工具，应明确调整产品范围，而非继续宣称完整方法学习。历史选择和运行结果仅在[研究目录](research/README.md)保留，不进入当前实施待办。
