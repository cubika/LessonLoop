# 评审与取舍

日期：2026-09-14。本文记录当前决定与调整条件。产品行为见[经验规则](02-experience-model.md)，组件见[系统架构](03-architecture.md)，验收门槛见[实施与验收](05-delivery-and-validation.md)。

## 当前决定

| 决定 | 理由 | 需要承担或验证的代价 |
|---|---|---|
| MemoryEngine 可替换，首选 Hindsight 自托管 | 复用原生提取、归纳、来源关联和检索 | Windows 依赖、原生结果映射、纠正和删除传播尚待实测 |
| 产品保留稳定发布记录与用户控制 | 引擎重处理不能丢失停用、修订或永久忘记意图 | 要维护原生产物绑定和对账，不能把候选直接作为指导 |
| 准入、依据和当前适用性分开 | 有用不等于有依据；有效经验也可能不适合本次任务 | 分别测漏学、噪声、条件完整性与实际收益 |
| L1–L5 只表示抽象层次 | 高层标签不代表可靠性 | 限定主题中验证真实推导和迁移，不奖励无依据泛化 |
| 自动召回、核实与采用前刷新 | 在相关任务中及时使用，并阻止过时建议继续取得资格 | 宿主能力要实测；只能控制新的投递，不能回收已交付文本 |
| 来源摘录保持短小，完整材料有保留期限 | 便于解释且控制资料副本 | 引擎原文、分块与派生结果需逐项清点；保留政策未满足前不能宣称已完成清理 |
| 单用户本地服务，统一 CLI/UI/代理入口 | 减少状态分歧和本地运维 | 首期一个写协调者，异常操作保留到核实完成 |
| 固定版本 Windows 安装包与私有依赖 | 用户无需从源码运行或手工部署数据库 | 用真实发行字节验证安装、健康、登录、升级和回滚 |
| AgentAdapter 与 Connector 分开 | 工作代理和长期来源的生命周期不同 | 共用核心合同，各自验收宿主协议与同步语义 |

## 已替代的原型选择

Mem0 OSS、Qdrant 单数据库和领域提取后 infer:false 写入已经退出实现范围，相关代码和依赖已删除。MemoryGateway 曾同时处理厂商 API、Qdrant 查询和控制记录；目标拆分为引擎适配与产品存储。Mem0 ID、nonce、双 collection 和 scroll 的细节保留在[历史设计](research/2026-09-13-p0/mem0-architecture.md)。

选型研究提供能力依据，未证明 Hindsight 在本项目任务中更好。现有 Mem0 报告也不能继承为新引擎通过结果。更换方案时继续使用相同产品合同，各后端单独给出实现与运行证据。

## 什么情况需要重新讨论

Hindsight 默认 Windows 发行配置无法运行、保留/删除边界无法满足，或适配需要大幅重写原生能力时，应先保留最小复现，再评估后端或范围。不能静默改成付费云服务、扩大资料保留或恢复已停用经验来通过测试。

完整任务对照没有减少重复工作，或引入更多误用、维护和核实成本时，先调整学习与召回流程，再扩展 UI 和真实 Connector。模型、引擎、提示词和预算变化分别记录，避免把多个变化混成一个收益结论。

代码评审核对验收 ID、场景断言和运行证据，方法见[实现质量评估](09-quality-evaluation.md)。历史材料及实测范围见[研究索引](research/README.md)。
