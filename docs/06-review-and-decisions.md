# 评审与取舍

日期：2026-09-13。本文说明 LessonLoop 的设计决策、适用边界与验证要求，供产品和开发评审使用。详细合同以[架构](03-architecture.md)和[经验模型](02-experience-model.md)为准。

## 产品与技术决策

| 决策 | 理由 | 接受的代价 |
|---|---|---|
| Mem0 管理经验，Qdrant 是唯一数据库 | 统一经验、向量和字段索引的存储，减少运维与一致性负担 | Mem0 接口未暴露的字段查询、分页由网关封装 |
| 领域提取后逐条 infer:false 写入 | 每条经验有独立的条件、例外、来源与层次，使用公开接口完成映射 | 默认提取与去重不执行，领域层需要自行实现和评测 |
| 准入、依据与使用状态分开 | 临时要求不长期入库，正确性不等于价值，用户偏好不等于事实 | 需要按内容类型验证与独立评测噪声/漏学/后续收益 |
| held 带有限复评计划 | 不确定 proposal 不构成永久候选库 | 过期 unresolved 停用；少量显式保留假设需要用途与核实问题 |
| L1–L5 与证据程度分开 | 抽象层次不能代表真实性，原则也可以由用户直接提供 | 高层推导需要独立的正反样本和迁移验证 |
| 语义查询与精确/字段查询分别声明模式 | 不同检索方式有不同匹配和排序语义 | 精确保证仅覆盖已索引值，不能承诺任意正文词召回 |
| 授权集合与适用上下文独立 | 经验可跨仓库、领域和流程复用，采集位置不限制未来用途 | 明确不适用排除，缺少可核实当前条件时仅返回合格 lead |
| 自动召回时机固定 | 新任务开始召回、采用前定向刷新、实质新信息补召回，主动 MCP 为补充 | 宿主能力不足需明确降级，迟到结果不可跨任务注入 |
| 纠正回执基于实际结果 | 可靠接收、暂停事实、当前可召回新修订分别展示 | completed 不能冒充生效；快速合并，异步状态由客户端跟踪 |
| 召回用途与存储状态独立 | guidance 可采用，lead 引导检查，本次不适用不等于经验错误 | 适配端须保留用途、有限核实、采用前刷新；结果不自动提升可信度 |
| evidence 保持短小 | 默认只保存 1–2 条原文短摘录，详细父经验按需查看 | 复杂主张超出预算需拆分或暂缓 |
| 当前经验使用一个 revision | 编辑、来源变化及派生失效需要明确版本 | 首版不提供历史正文与回滚 |
| 本地单写者与有限管理记录 | 序列化修改，隔离未确认写入，支持重启后核对 | 未知结果可能暂时阻止使用或需要修复 |
| AgentAdapter 与 Connector 分开 | 代理工作流和长期外部同步各有接入合同，经验核心一致 | 通用同步运行模块与来源能力分别验收 |

首版使用 TypeScript 单个本地服务。模型、存储网关和扩展通过接口分离，先验证必要边界，再按实际需求拆分部署单元。

## 各视角的评审重点

| 视角 | 核心问题 | 设计要求与验收 |
|---|---|---|
| 用户 | 是否少做重复调查，是否需要长期整理卡片 | 默认自动提炼，可不产出；纠正后停止旧建议；用后续任务衡量收益 |
| 产品经理 | 是否用少存内容掩盖漏学，用层级标签代替学习 | 噪声和覆盖分别测量；限定主题中要求实际 L3/L5 推导与迁移结果 |
| 架构 | 应用是否重复实现通用存储，场景是否污染核心 | 经验写入走 Mem0，Qdrant 是唯一数据库；外部协议属于扩展 |
| 工程可靠性 | 超时、并发、删除与重启是否产生错误状态 | 管理写先确认；未确认操作不盲重放；读取复核当前内容与删除状态 |
| 使用成本 | 模型调用、元数据更新、维护工作是否过多 | 记录提取、整理、嵌入与修复成本，不把强制二次审查设为必要环节 |

## 必须保持的约束

材料的 role 是来源声称，可信通道决定实际归属。代理不能通过填写 user 或 tool 获得对应权威，原文摘录存在也不证明角色真实。

来源指纹按完整脱敏片段计算，引用和派生副本继承它。字段索引用于定位；来源删除仍检查当前经验和作业内容。历史快照恢复需要保留并应用现有删除记录，不能把旧删除记录一同回滚后直接开放读取。

当次上下文核实与经验主张补证走不同接口：target recall 不改记录，verificationFor 经准入后才可能修订。两类召回均不得绕过来源/授权/生命周期，条件未知不能凭猜测转为 guidance。

自然语言纠正必须绑定目标修订。明确的用户纠错先阻止目标建议，再处理修订；代理转述不能伪装成用户授权。

metadata 不会自动进入语义检索。检索字段改变时，网关同次更新 memory 文本与结构。指定 exceptions 的字段查询只用于调查，不能因为匹配了例外就建议执行。

Qdrant 不等于应用事务队列。所有已发写操作确认结束前，不能发布完整导出；同一操作的报错、超时或查无结果也不证明持久写没有发生。

## 验证状态与调整条件

现有依据是设计静态评审和固定版本的官方资料核验，没有 Mem0/Qdrant 运行验证或用户收益数据。进入 P0 后，先验证结构字段往返、前置筛选、分页、无 SQLite 运行、管理记录持久化与未知写隔离。

如果接口适配需要过多自研代码，或维护成本超过提炼带来的价值，应先拿最小复现和测量结果调整范围。本文存储取舍描述现有 Mem0/Qdrant 原型；[后续选型建议](research/2026-09-14-memory-selection/README.md)尚待新适配器实测。各阶段按[实施与验收](05-delivery-and-validation.md)的条件结束。文档检查只验证文档本身。

代码评审按[实现质量评估](09-quality-evaluation.md)核对验收 ID、场景断言和运行证据。行为正确性、经验质量、任务收益、运行与使用质量分别给结果；模型自评分、类型检查或实验正常结束不能互相替代。更换引擎时复用产品合同，另测后端实现，已有失败和必测缺项须进入报告。
