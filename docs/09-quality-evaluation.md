# 质量评估方法

日期：2026-09-14。状态：当前评估规范，完整执行器尚未实现。验收ID、规模和门槛统一在[05](05-delivery-and-validation.md)，本页定义怎样测量。

## 评估对象

| 对象 | 判断内容 | 不能替代它的指标 |
|---|---|---|
| 工作案例 | 关键动作、观察、结果和来源对应，缺口明确 | 会话摘要长度、保存次数 |
| L1–L5产物 | 实际经历、关联、解释、条件模式和原则是否由材料支撑 | level字段、因果词或原生对象类型 |
| 方法 | 步骤/分支/检查能否指导任务，新的结果是否改变具体做法 | 方法标题、卡片数量、普通改写 |
| 任务使用 | 当前路径适用、执行结果、无效尝试与额外成本 | 召回命中、引用声明或模型自评 |
| 控制与运行 | 权限、修订、来源失效、恢复、安装和回执 | 代码覆盖率、文档校验通过 |

分别报告这些结果。用户体验和产品方向由01定义，评测不以字段齐全代替方法能力，也不要求普通用户逐条审核。

## 从验收要求到场景合同

每个场景固定scenarioId、family、关联验收ID、profile、输入/来源家族、初始状态、操作顺序、预期结果、禁止结果、判定方法及需保存的产物。运行前声明必测与诊断项，不在失败后改为跳过。

方法场景额外标注关键步骤、可接受分支、完成条件和更新方向。允许等效做法，不强制参考答案措辞。WorkCase、Experience、Method及原生引用分别记录，不能把一个会话拆分为多份独立成功样本。

参考答案、评审标签和未来任务不传给提炼器。程序检查状态、版本、来源位置与实际文件；语义判定核对有用性、支持、条件和方法变化。模型可辅助筛查，不能同时生成答案并担任唯一发布评委。

## 分层提炼判定

| 层次 | 有效判定 |
|---|---|
| L1 | 从真实材料提取关键经历，区分观察与陈述，保留失败及未知 |
| L2 | 找到实际共同变化，保留样本范围与同源关系，不把共现当因果 |
| L3 | 解释与机制证据相关，未排除的替代解释保留，不能靠caused_by标签通过 |
| L4 | 正反案例形成可判断的条件、步骤和例外，不仅把摘要编号 |
| L5 | 概括共同决策方式，在较晚新对象上合理应用，不只是替换通用名词 |

各层有足证正例和不足证反例。全拒、全held或只产出低层不能通过高层正例验收；高层数量也不奖励。两位独立评审标注并仲裁分歧，数据和判定器都有版本。

## 方法贯穿场景

使用“生成文件修改”案例族：历史材料包含手工修改被覆盖、修改生成源后检查通过和手写目录反例。真实提炼后形成方法，下一任务先诊断再分支，检查实际产物。随后新增扩展区例外，要求具体修改分支并保留原有效路径，再用未见任务检验。

同时覆盖用户纠正、原生重处理、投影延迟、案例到期和来源撤回，检查方法没有被错误恢复。缺少关键初态或工具结果时记录不足，不能手工填正确方法后把下游成功当提炼成功。

## 数据划分与日常场景

开发场景按工作案例、分层产出、方法形成/推进/更新、来源与写恢复、宿主、Connector、回顾、导出和发行组织。现有48个窗口是开发材料，需要补方法任务与独立判定；它们不是48个独立收益样本。

按来源家族和时间划分，原文、转发、改写与同一任务变体进入同一分区。较早材料生成方法，较晚任务评估迁移；已经用于调试或驱动修订的案例进入开发集，不能再次宣称未见。

数据标签记录依据、分歧和仲裁，修订错误标签时重评所有相关版本，不只修有利样本。用户授权的线上案例可以显式导出开发样本，周报和自动分类不能当gold label。

## 对照、重复运行与引擎更换

三组为无额外记忆、合理配置的Hindsight官方方案、同一引擎上的LessonLoop方法学习。官方组保留正常摄取、归纳和回填，不能简化为裸检索API。主要增量比较是官方组与产品组，无记忆组说明底座效果。

冻结引擎/官方插件/宿主版本、模型、missions、范围、历史材料、工具权限和预算。额外历史扫描、git摄取和代码调查只在纳入实验时开启，避免不同组获得额外材料。每组独立数据目录和学习过程，不能共享前组结果。

开发阶段默认每任务每组独立运行3次观察波动，重复按同一任务聚合，不变成独立用户样本。发布规模与门槛按05冻结，顺序随机或交叉，评审尽量不知道分组。所有失败、超时和预定重试都报告，不挑最好一次。

更换引擎后重新运行能力合同及方法场景，保留同一产品语义。原生分数不可跨引擎直接比较；部分缺项与代价单列，不继承其他版本或其他后端的通过结果。

## 指标与解释

Precision@3按找到且能正确准备的条目计，Recall@3按提前标注的最多3个核心目标计；lead按缺口是否值得核实评价。错误范围、条件不符、失效记录和未核实路径均不是有效命中。错误或超时的空结果不计正确不建议。

方法变化按实际新增步骤、改变顺序、分支、例外或停止条件判断。重复工作用预定义调查单元与真实轨迹核对，工具总调用数不直接等于浪费。完成质量先于省时，新增核实与维护成本完整计入。

报告分子、分母、逐任务配对差值和不确定性。零分母N/A，未知成本不填零；底层订阅调用也记录用量。线上回顾只描述观察，不能用引用率或前后趋势取代随机/配对对照。

## 状态、报告与门禁

runStatus=completed/error/blocked表示执行过程；gateStatus=passed/failed/blocked表示评价。已确认违规优先于缺项，失败和未测列表同时保留。退出码依次为0、1、2；正常运行结束不等于通过。

报告至少包含profile、产品/上游版本、工作区差异摘要、材料/标签/判定器版本、命令、环境、计划场景、实际产物、各断言结果、指标和限制。必测无缺项才可通过；模拟、真实后端、真实模型和真实宿主分别说明。

文档检查验证链接、结构和示例，代码检查验证对应实现；两者都不能证明新方法学习能力。修改哪些模块就运行对应合同，完整阶段退出和发布才运行完整profile。不要为文档改写启动生产任务或重复外部操作。

## 现有工具与实施

当前可用的是npm run validate:docs、npm run validate:evals、npm run typecheck、npm test及Copilot协议探针。evals/lib/experience.ts为Experience子集检查，task-runner基于两个实际文件任务；没有WorkCase/Method学习或官方三组对照。

先完成P0最小切片和可判定的报告，再在P1/P2扩完整学习和方法变化，P3验证正式界面、宿主、回顾及发行。材料说明见[evals](../evals/README.md)，宿主说明见[probes](../probes/copilot/README.md)。
