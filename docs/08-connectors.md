# Connector 持续同步

日期：2026-09-13。状态：待实现的接口与产品设计。Connector 将外部材料或已整理经验持续同步到 LessonLoop，邮件、笔记、文档目录、知识库、工单和复盘记录都是可接入的来源示例，不表示这些具体集成都已实现。

## 职责边界

| 组件 | 负责什么 | 不负责什么 |
|---|---|---|
| Connector | 外部认证、对象读取、原生分页/变更检测、内容转换、源能力声明 | 直接写 Mem0、授予经验可信状态、管理经验生命周期 |
| ConnectorRuntime | 连接配置、通用定时、重试/限流、接收确认、游标、背压与状态展示 | 邮件线程语义、特定知识库协议、L1–L5 推导 |
| LearningCore | 材料校验、价值判断、经验提炼、去重、适用性、修订和来源失效 | 识别外部 API 协议或轮询邮箱 |
| AgentAdapter | 代理会话的实时材料采集和经验消费 | 通用长期资料同步；Copilot plugin 是此类适配 |
| ExtractionModel | 执行受控模型推理 | 来源认证、同步游标和数据库状态 |

ConnectorRuntime 是本地服务的扩展运行模块，和学习作业调度分开。它复用定时、限流与状态管理，具体 Connector 只实现外部协议。数据继续使用同一 Qdrant；所有经验写入经核心 Mem0 网关。

首期 Connector 是显式注册的 TypeScript 模块，可随安装包或独立扩展包交付。它不是 Copilot plugin，不要求代理在线，不引入插件市场或另一数据库。外部程序也可通过认证客户端提交统一同步批次。

## 定义与连接实例

ConnectorDefinition 表示实现类型及其能力；Connection 表示用户配置的一次连接，例如同一文档 Connector 可以有两个目录连接，分别同步到不同 scope。实例有独立账号绑定、筛选范围、游标与状态。认证凭据仍放系统凭据设施，仅保存凭据引用。

| 配置 | 首期含义 |
|---|---|
| connectorType / connectorVersion | 已注册实现与配置格式兼容版本 |
| connectionId | 服务生成的实例 ID；绑定来源账号/目录身份，不能复用为不同来源 |
| targetScopeId | 一个目标知识集合，由用户授权；不接受源内容指定其他集合 |
| sourceSelection | 目录、集合、标签、时间边界等外部筛选；由 Connector 定义格式 |
| mode | scheduled_pull 或 authenticated_push |
| schedule | 周期与限流预算；可手动 syncNow；暂停后不再拉取 |
| initialRange | 明确的初始回填范围；不默认抓取所有历史 |
| deletionPolicy | 默认 withdraw；可预先授权 erase |
| credentialsRef | 系统凭据引用，非秘密值 |

连接状态为 active/paused/needs_auth/error。UI 还显示读取进度、已接收待学习量、学习失败量和最近成功时间；“拉取成功”不能显示成“经验已更新”。同一实例仅允许一个同步运行，额外触发合并为下一次运行。

## 输入与接口

源可以提供原始材料，也可以提供已经整理好的经验草稿。两者都经核心来源、范围、条件与重复检查，不能把外部 state、assessment、review、ID 或 revision 直接映射成可信内部值。经验草稿可以减少重复提取，但不绕过校验；不得将外部文字指令当成授权。

| 输入种类 | 内容 | 核心处理 |
|---|---|---|
| material | 文章片段、邮件段落、记录或说明 | 按统一 Material 契约提炼 |
| experience_draft | 结论、条件、层次建议及实际来源片段 | 校验后规范化，必要时补充提炼，再整合 |
| source_delete | 来源明确报告对象删除或用户发起连接清理 | 按已配置政策撤回或清理关联来源，不直接删除共享经验整条记录 |

只提供外部原则时，原文只构成 external/reported 来源；转发、第一人称模板和命令句不变成当前用户的 constraint。只有用户在可信通道明确采用为本人/其管理范围的规范，才形成对应用户约束。外部事实/流程须 supported 才可 active；不足时按准入规则拒绝或显式保留为有限 held，不伪造实验、工具结果或用户确认。来源原件的不可用通知属于连接状态，不等同 source_delete。

首期接口行为如下，方法名是应用设计，不是外部厂商 API：

| 接口 | 调用方与作用 |
|---|---|
| checkConnection(config) | Runtime 检查认证、读取能力、稳定对象身份与删除检测能力 |
| readPage(checkpoint, limits) | 拉取 Connector 返回有界 SourceChange 列表与候选 nextCursor |
| normalize(item) | Connector 将一个对象转换为 material 或 experience_draft，并保留来源归属 |
| ingestChanges(connectionId, batch) | 已认证 Connector 提交，服务逐项返回 accepted/unchanged/ignored/retryable/rejected |
| syncNow / pause / resume / disconnect | 用户通过 CLI/UI 管理实例；不让材料内容修改连接配置 |

SourceChange 包含 sourceKey、changeType、可选 sourceVersion、实际 sourceUpdatedAt、可选 locator，以及脱敏后的输入。sourceKey 是连接内稳定的对象身份，例如文档键或消息键；sourceVersion 是提供商的变更令牌，不要求可排序。它们只存在于同步管理状态，不成为每条 Experience 的必填字段或事件账本。

每个内容块仍遵守 Material 32 KiB/16 segments 限制；一次外部对象修订最多拆为 8 个材料作业。更长对象必须由 Connector 声明稳定子资源分片或明确返回需缩小输入范围，不能悄悄截断。输入需要分片时，版本与稳定 partKey 覆盖整个对象修订，变化不能被误判为另一个独立来源。

SourceChange 的一个 upsert 必须包含该对象修订的完整有界 partKey 清单和 complete=true，最多 8 项；所有正文片段需要可靠接收，才允许提交本次替换。分页尚未完成、分片缺失或快照不完整时，不因缺少某一片段而撤回原来源。超长对象拆成稳定子资源后，默认按子资源分别管理；只有完整且有界的父对象清单确认后，才能传播父对象级删除，不承诺无清单的整对象替换。

## 拉取、推送与删除能力

默认实现周期增量拉取：首次按 initialRange 回填，随后从已确认游标继续。时间窗型来源使用重叠窗口再去重，不只保存本机当前时间来判断未处理数据。来源不提供可靠增量时，可使用有界全量比较，但必须说明覆盖范围与成本。

推送只通过已认证入口接收。首版本地服务不直接开放公网 webhook；远端变更可由连接器进程拉取后提交。支持通知型推送时，通知只触发重读当前源对象，避免乱序内容覆盖。只有源提供可核验的单调序列时才直接接收有序快照更新；opaque version、邮件时间和本机接收时间不能用于判断新旧。

Connector 必须声明能否发现删除。滚动“最近 N 天”查询中不再出现某条对象，不代表它被删除；列表分页失败或部分扫描也不能推断删除。无删除信号的来源，只能在完整受控对账或明确用户操作后撤回，UI 显示此能力限制。

网络超时、临时 404、401/403 或来源故障首先标记同步不可用并停止游标前移，不假造删除。已确认撤销读取权限时，设置连接级来源使用暂停，相关经验暂不自动建议，等待重新授权或用户清理；普通暂时性故障不自动抹除经验。

## 接收确认与持续运行

每个 Connection 的来源比较、源绑定和检查点修改经同一 Runtime 串行完成，经验写仍经核心单写者。Qdrant 多点更新不是事务，必须定义以下顺序：

1. 验证连接身份与范围，规范化源对象，计算内容摘要。重复版本与内容不再次创建学习任务。
2. 为完整变化对象持久化 source_binding 的 pending 修订和稳定作业身份，再持久化所有对应材料作业。服务以 bindingId+sourceRevision+partKey 稳定生成 LearningJob ID，重试核对同一身份；结果未知不返回 accepted。
3. 所有片段已可靠接收后，确认旧修订的来源失效标记持久化，登记 pending 已接收并允许学习。页面所有项目均完成此确认、确认 unchanged，或持久记录 ignored/rejected 原因后，才确认 nextCursor。未持久化或不完整项目不能被游标越过。
4. 学习在后台执行。所有 parts 到达 completed、明确终结 failed 或 ignored，且没有 uncertain 后，核对源修订并登记成功/部分/失败结果，将 current 更新为该已处理修订，再结束 pending。失败不显示为已学会，旧来源失效标记不撤销；允许重新读取后续修正版，人工重试复用相应失败项而非重复已成功部分。
5. 已接收但尚未完成/确认的材料不适用“完成后 7 天清理”。明确失败保留错误项，可重试；材料最终到期时必须先保留可定位来源的失败状态，界面显示未学到，不悄悄丢掉。

游标前进表示源数据已可靠接收，不表示提炼已经成功。UI 分开显示这两种进度。重复页面、响应丢失和重启都用 source_binding 与绑定作业恢复，不能用语义 top-k 判断“似乎没写”。

每个来源对象只保留 current 与一个 pending 修订。pending 未结束时，不覆盖其已接收输入；对同源新变化返回 retryable/背压，或在其完成后重新读取源的最新快照。首版承诺最终跟进可访问对象的最新状态，不保证保存源在两次轮询之间的全部历史版本。不同连接按预算公平调度，避免一个来源长期占满学习队列。

队列容量、每日模型额度、限流退避与网络失败均不会推进未确认游标。服务停机后从最后确认位置恢复，错过的定时触发合并为追赶运行，不并发补执行每个时刻。

## 源对象身份与经验来源

持续同步需要一个稳定的来源绑定，但不需要保存每次轮询事件。source_binding 按 `(connectionId, sourceKey)` 唯一，保存提供商版本、内容摘要、本地 sourceRevision、当前/待处理的来源指纹、作业关联与结果状态。它是一个对象的当前同步状态，不是完整源历史。

sourceRevision 由服务在接受真正的新内容时递增。原生版本只用于相等判断或来源明确保证的顺序；同内容重复提交沿用当前/待处理修订。先前内容后来恢复成相同文本，也属于新的已确认源修订，不复用已失效来源标识。

连接还保存 transformRevision，纳入影响材料的转换、筛选和分片配置版本。此类配置改变需重新扫描，即使源正文未变也可形成新的材料修订；凭据轮换和调度间隔改变不制造内容新版本。改变账号/源身份或目标 scope 必须新建连接并明确重新导入，既有经验不自动迁移或扩大授权。

手动材料继续使用 scope+规范化片段正文的 fingerprint。Connector 材料的 fingerprint 使用 scope、服务生成的 bindingId、sourceRevision、partKey 和规范化片段正文进行长度分隔编码后计算 SHA-256。所有重试使用已持久化的相同绑定与修订。原生 sourceKey 和账号细节不暴露到经验记录；evidence 仍仅保存短摘录与指纹。

这使一个对象的新修订不会被旧修订撤回误伤，相同文字的另一个来源也能保持独立归属。但不同指纹不自动等于独立证据：同源转载、转发、代理复述仍按已知共同归属处理；无法确定独立性时不增加支持。

## 更新、撤回与忘记

| 情况 | 处理 |
|---|---|
| 同源同内容再次读取 | unchanged，不新增任务、卡片或支持次数 |
| 同源内容真正变化 | 完整新输入已可靠接收后，先确认旧来源失效标记，再允许新提炼发布；按剩余依据重评受影响经验 |
| 权威 source_delete | 默认 withdraw：旧来源不再支持自动建议，短摘录可供检查；erase 政策才清除对应副本 |
| 确认读取权限被撤销 | 连接级暂停其来源的自动使用；不冒充逐项删除，重新授权后对账 |
| 用户删除某条经验 | 核心建立删除记录，Connector 同步不能自动复活同一目标 |
| 用户要求忘记一个源对象 | binding 标为 excluded；该对象后续修订也不再接收，恢复须用户显式操作 |
| 暂停或移除连接 | 默认停止新增读取，已接收学习继续，经验保留；可明确取消待办、撤回或清理来源 |

来源修订失效使用 reason=source_superseded 的临时来源标记，区别于 user_forget 永久拒收。权威删除的 withdraw/erase 也分别表达；不能用现有内容 fingerprint 的永久忘记来表示普通更新。状态记录仍存在 Qdrant 管理集合。

Connector 的每条来源控制标记还保存可索引的 bindingId 和对应指纹。current/pending 换代后，只要更早修订仍有引用或保留摘录，其标记就继续提供归属定位。忘记整个对象时，按 bindingId 收集 current/pending 和所有保留标记并清理，不只清理最新两版；无引用且不会重放后才清标记，不保存旧正文或完整版本库。

guidance 和 lead 均检查来源标记、连接级使用暂停与现有 sourceFingerprints；线索不能绕过 superseded/withdrawn/erased/user_forget 或撤销访问，其他内容出口继续执行各自授权查看规则。派生经验通过根指纹和父修订检查失效。暂时不可用的来源不直接删除多来源经验，核心先停止受影响建议，再根据剩余依据重提炼；保留的结论仍须满足所有条件。

用户编辑过的经验不能由 Connector 直接覆盖。先区分真实用户设定的规范与客观事实：外部模板/建议不覆盖也不暂停其本人偏好或有权设置的要求；同条件的实质事实矛盾才按证据进入带 review 的 held。新来源仅是修订提案，不能借重复同步重启 disabled 或刷新复评期限。

正在核实的线索遇到源对象更新、撤回或连接权限变化，下一次定向 recall 必须重新检查，不能因先前缓存是 lead 就转为 guidance。核实当前上下文本身不改来源版本或同步游标。

未完成任务在写入前重新检查 binding 当前/待处理修订及失效标记。uncertain 写按核心恢复规则隔离；不能在源已改变后恢复并发布旧结论。source_superseded 标记仅在全部旧作业终止且无当前经验仍引用后清理；源绑定与临时标记不能按普通完成任务的期限提前丢弃。

标记清理还须确认协议不会把迟到的旧快照重新接收为新修订：无单调版本的推送只能触发重读当前对象。保留经验的解绑会保留仍被引用的精简 source_binding 和来源说明；停止同步不等于可删除所有映射。

## 最小持久化补充

沿用一个 Qdrant 管理 collection，新增逻辑 recordType，不增加数据库或原始材料档案：

| recordType | 内容 | 边界 |
|---|---|---|
| connection_config | Connector 类型/版本、transformRevision、目标 scope、来源筛选、计划、删除政策、凭据引用 | 最大 16 KiB；真实秘密不入 payload |
| connection_state | 已确认 cursor、当前运行、重试时间、接收/学习计数、连接与来源使用状态 | 最大 16 KiB；cursor 最大 8 KiB；不保存正文 |
| source_binding | 连接+源对象身份、内容摘要、递增 sourceRevision、current/pending 指纹与 job 映射、excluded | 最大 32 KiB；仅两份修订元信息，每份最多 8 个作业、128 个片段指纹；内容在短期 LearningJob |

sourceKey 原值最多 512 B，超过时 Connector 提供稳定可逆定位或声明不支持，不静默截断；绑定 ID 使用服务确定性映射。job 增加可选 bindingId/sourceRevision/partKey，同步来源必填。对接现成经验也不绕开单记录 16 KiB 与轻量 evidence 约束。

来源标记复用管理层标记机制，增加 reason=source_superseded/source_withdrawn/source_erased/user_forget、bindingId 与处理动作；它不写入 Experience.state 的新枚举。用户查看的是正在同步、已接收待学习、部分失败和需要认证，不显示 binding/nonce。

## UI、CLI 与交付

Web UI 提供 Connectors 页面：添加连接、选择来源范围与目标集合、配置频率、预览首轮处理范围、立即同步、暂停/恢复、重新认证和移除。详情展示接收进度与学习进度、近期失败来源和重试入口。移除默认保留经验，撤回或清理必须是明确选项。

CLI 提供同等的 list/add/check/sync/pause/resume/status/retry/remove 能力，命令拼写在实现时固定。SDK 提供 Connector 契约和认证批次接收入口，不暴露 Mem0/Qdrant 直写。

通用 ConnectorRuntime、输入契约和管理 UI/CLI 属于产品平台能力。具体 EmailConnector、文档目录等是独立实现。P1 验证标准输入，P3 提供通用连接管理与一个可复现的样例 Connector，P4 再按需求增加真实来源。邮件不是平台核心字段或唯一交付目标。

## 验收案例

| ID | 场景 | 必须结果 |
|---|---|---|
| K01 | 两种不同来源实现相同 Connector 契约 | 不修改 Experience schema 或 LearningCore |
| K02 | 首次回填、重叠窗口、重复页面 | 同源同修订只接收一次，不重复支持 |
| K03 | 页面部分项目落盘失败、接收响应丢失 | 不跳游标；重试复用已确认任务 |
| K04 | 游标已推进但提炼失败/服务重启 | 来源可定位，任务可恢复，UI 不显示已学完 |
| K05 | 一份文档只改一段或恢复先前内容 | 新修订可被接收；不被旧内容忘记标记误伤 |
| K06 | 两个对象有相同文字，只删除其中一个 | 仅处理对应来源归属，核心按剩余证据重评 |
| K07 | 来源删除、权限撤销、临时不可用 | 三种行为可区分；不从滚动窗口缺项推断删除 |
| K08 | 乱序推送与 opaque version | 重取当前快照或按已声明单调序列处理，不按字符串比较版本 |
