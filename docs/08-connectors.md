# Connector 持续同步

日期：2026-09-14。状态：待实现的持续同步合同。本文定义连接、增量接收和来源生命周期；字段容量与指纹见[数据模型](07-storage-model.md)，经验准入见[领域模型](02-experience-model.md)。邮件、笔记、文档目录、知识库、工单和复盘记录是来源示例，具体支持情况须逐个实现和验证。

## 职责边界

| 组件 | 负责什么 | 不负责什么 |
|---|---|---|
| Connector | 外部认证、对象读取、原生分页/变更检测、内容转换、源能力声明 | 直接写记忆引擎、授予经验可信状态、管理经验生命周期 |
| ConnectorRuntime | 连接配置、通用定时、重试/限流、接收确认、游标、背压与状态展示 | 邮件线程语义、特定知识库协议、L1–L5 推导 |
| LearningCore | 材料校验、价值判断、经验提炼、去重、适用性、修订和来源失效 | 识别外部 API 协议或轮询邮箱 |
| AgentAdapter | 代理会话的实时材料采集和经验消费 | 通用长期资料同步；Copilot plugin 是此类适配 |
| ExtractionModel | 执行受控模型推理 | 来源认证、同步游标和数据库状态 |

ConnectorRuntime 在本地服务中运行，负责通用定时、限流和同步状态，与学习作业调度分开。各 Connector 只实现来源协议，数据与经验均通过核心接口管理，由记忆适配器映射实际后端。

首期 Connector 以显式注册的 TypeScript 模块交付，随固定版本核心组件包或兼容扩展包安装，不在用户机器上编译。同步不要求代理在线，也不依赖 Copilot plugin；关闭 UI 后后台继续，注销或关机时暂停，恢复后从确认游标追赶。首期不设插件市场，外部程序可以通过认证客户端提交统一格式的同步批次。程序升级与卸载保留源绑定、游标和用户配置，具体以[发布与安装](10-distribution-and-installation.md)为准。

## 定义与连接实例

ConnectorDefinition 描述一种实现及其能力，Connection 是用户配置的连接实例。例如，同一个文档 Connector 可以连接两个目录，各自同步到不同 scope。每个实例分别保存账号绑定、筛选范围、游标和状态；秘密凭据放系统凭据设施，配置中只存引用。

| 配置 | 首期含义 |
|---|---|
| connectorType / connectorVersion | 已注册实现与配置格式兼容版本 |
| connectionId | 服务生成的实例 ID；绑定来源账号/目录身份，不能复用为不同来源 |
| targetScopeId | 一个目标知识集合，由用户授权；不接受源内容指定其他集合 |
| sourceSelection | 目录、集合、标签、时间边界等外部筛选；由 Connector 定义格式 |
| mode | scheduled_pull 或 authenticated_push |
| schedule | 周期与限流预算；可手动 syncNow；暂停后不再拉取 |
| initialRange | 明确的初始回填范围；不默认抓取所有历史 |
| deletionPolicy | 默认 withdraw；可预先授权 erase |
| credentialsRef | 系统凭据引用，非秘密值 |

连接状态取 active/paused/needs_auth/error。UI 分开显示读取进度、待学习数量、失败数量和最近成功时间，不能把拉取成功写成经验已更新。同一实例同时只运行一次同步，额外触发合并到下一次。

## 输入与接口

来源可提供原始材料或整理过的经验草稿。核心都要检查来源、范围、条件和重复内容；外部 state、assessment、review、ID、revision 不能直接成为内部受信值。草稿可以省去部分重复提取，不能跳过校验，文本中的指令也不构成授权。

| 输入种类 | 内容 | 核心处理 |
|---|---|---|
| material | 文章片段、邮件段落、记录或说明 | 按统一 Material 契约提炼 |
| experience_draft | 结论、条件、层次建议及实际来源片段 | 校验后规范化，必要时补充提炼，再整合 |
| source_delete | 来源明确报告对象删除或用户发起连接清理 | 按已配置政策撤回或清理关联来源，不直接删除共享经验整条记录 |

外部原则保留 external/reported 归属，不能冒领当前用户的 constraint 或支持状态；事实、流程和显式保留的假设统一按[准入规则](02-experience-model.md#准入先判断是否该记再判断能否用)处理。

首期接口行为如下，方法名是应用设计，不是外部厂商 API：

| 接口 | 调用方与作用 |
|---|---|
| checkConnection(config) | Runtime 检查认证、读取能力、稳定对象身份与删除检测能力 |
| readPage(checkpoint, limits) | 拉取 Connector 返回有界 SourceChange 列表与候选 nextCursor |
| normalize(item) | Connector 将一个对象转换为 material 或 experience_draft，并保留来源归属 |
| ingestChanges(connectionId, batch) | 已认证 Connector 提交，服务逐项返回 accepted/unchanged/ignored/retryable/rejected |
| syncNow / pause / resume / disconnect | 用户通过 CLI/UI 管理实例；不让材料内容修改连接配置 |

SourceChange 包含 sourceKey、changeType、可选 sourceVersion、实际 sourceUpdatedAt、可选 locator，以及脱敏后的输入。sourceKey 是连接内稳定的对象身份，例如文档键或消息键；sourceVersion 是提供商的变更令牌，不要求可排序。它们只存在于同步管理状态，不成为每条 Experience 的必填字段或事件账本。

每块内容遵守 Material 的 32 KiB/16 segments 限制，一次对象修订最多拆成 8 个材料作业。超长对象须由 Connector 定义稳定子资源，或返回需要缩小输入范围的错误，不能截断后继续。分片的版本与稳定 partKey 须覆盖整个对象修订，避免把内容变化当成独立来源。

SourceChange 的 upsert 必须带完整 partKey 清单和 complete=true，最多 8 项。所有片段可靠接收后，才能提交本次替换。分页未完、片段缺失或快照不完整时，不得按缺项撤回原来源。

超长对象拆成稳定子资源后，分别管理各子资源。父对象级删除须以完整且有界的父清单为依据；没有清单时，不支持整对象替换。

## 拉取、推送与删除能力

默认按周期增量拉取：首次处理 initialRange，随后从已确认游标继续。时间窗来源使用重叠窗口并去重，不能只拿本机当前时间判断哪些数据尚未处理。没有可靠增量接口时，可在明确范围内做全量比较，并说明覆盖范围和成本。

推送入口必须认证。首期本地服务不开放公网 webhook，远端变更由连接器拉取后提交。通知型推送只触发重读当前对象，以免乱序内容覆盖新版。源能提供可核验的单调序列时，才直接接收快照更新；opaque version、邮件时间和本机接收时间不能代替版本顺序。

Connector 须声明是否支持删除检测。“最近 N 天”列表里不再出现某对象，或分页失败、扫描不完整，都不能推断删除。来源没有删除信号时，只能通过完整受控对账或明确用户操作撤回，UI 需说明限制。

网络超时、临时 404、401/403 或来源故障时，标记同步不可用并停止推进游标，不推断删除，也不凭临时故障停用已有经验。已有经验仍按有效期、来源控制和其他资格判断。确认读取权限已撤销后，暂停该连接来源的自动使用，等待重新授权或用户清理。

## 接收确认与持续运行

每个 Connection 的来源比较、源绑定和检查点修改经同一 Runtime 串行完成，经验写仍经核心写协调。接收与发布须按以下顺序确认；原型的 Qdrant 多点写入和新后端分别验证恢复行为：

1. 验证连接身份与范围，规范化源对象，计算内容摘要。重复版本与内容不再次创建学习任务。
2. 为完整变化对象持久化 source_binding 的 pending 修订和稳定作业身份，再持久化所有对应材料作业。服务以 bindingId+sourceRevision+partKey 稳定生成 LearningJob ID，重试核对同一身份；结果未知不返回 accepted。
3. 所有片段已可靠接收后，确认旧修订的来源失效标记持久化，登记 pending 已接收并允许学习。页面所有项目均完成此确认、确认 unchanged，或持久记录 ignored/rejected 原因后，才确认 nextCursor。未持久化或不完整项目不能被游标越过。
4. 学习在后台执行。所有 parts 到达 completed、明确终结 failed 或 ignored，且没有 uncertain 后，核对源修订并登记成功/部分/失败结果，将 current 更新为该已处理修订，再结束 pending。失败不显示为已学会，旧来源失效标记不撤销；允许重新读取后续修正版，人工重试复用相应失败项而非重复已成功部分。
5. 已接收但尚未完成/确认的材料不适用完成清理期限。明确失败保留可重试项；材料最终到期前必须保留可定位来源的失败状态，界面显示未学到。具体期限见[材料保留合同](07-storage-model.md#材料与派生产物保留)。

游标前进表示源数据已可靠接收，不表示提炼已经成功。UI 分开显示这两种进度。重复页面、响应丢失和重启都用 source_binding 与绑定作业恢复，不能用语义 top-k 判断“似乎没写”。

每个源对象只保留 current 和一个 pending 修订。pending 未结束时，其已接收输入不能被覆盖；新变化返回 retryable/背压，或等它结束后重读最新快照。首版跟进可访问对象的最新状态，不保存两次轮询之间的全部历史。各连接按预算公平调度，避免一个来源长期占满学习队列。

队列容量、每日模型额度、限流退避与网络失败均不会推进未确认游标。服务停机后从最后确认位置恢复，错过的定时触发合并为追赶运行，不并发补执行每个时刻。

## 源对象身份与经验来源

source_binding 以 `(connectionId, sourceKey)` 唯一定位一个对象，保存提供商版本、内容摘要、本地 sourceRevision、current/pending 指纹、作业关联和结果状态。同步只维护这份当前状态，不记录每次轮询事件或完整源历史。

sourceRevision 由服务在接受真正的新内容时递增。原生版本只用于相等判断或来源明确保证的顺序；同内容重复提交沿用当前/待处理修订。先前内容后来恢复成相同文本，也属于新的已确认源修订，不复用已失效来源标识。

transformRevision 记录影响材料的转换、筛选和分片配置版本。配置改变后重扫，正文没变也可能形成新材料修订；凭据轮换或调度间隔变化不产生内容版本。换账号、源身份或目标 scope 时须新建连接并明确重新导入，已有经验不自动迁移或扩大授权。

所有重试使用已持久化的相同绑定、修订和 partKey。fingerprint 公式统一见[来源指纹](07-storage-model.md#evidence-与来源指纹)；原生 sourceKey 和账号细节不暴露到经验记录，evidence 仍只保存短摘录与指纹。

这使一个对象的新修订不会被旧修订撤回误伤，相同文字的另一个来源也能保持独立归属。但不同指纹不自动等于独立证据：同源转载、转发、代理复述仍按已知共同归属处理；无法确定独立性时不增加支持。

## 更新、撤回与忘记

| 情况 | 处理 |
|---|---|
| 同源同内容再次读取 | unchanged，不新增任务、卡片或支持次数 |
| 同源内容真正变化 | 完整新输入已可靠接收后，先确认旧来源失效标记，再允许新提炼发布；按剩余依据重评受影响经验 |
| 网络超时或来源暂时不可用 | 停止同步和游标推进；不新增来源失效标记，既有经验继续按自身资格判断 |
| 权威 source_delete | 默认 withdraw：旧来源不再支持自动建议，短摘录可供检查；erase 政策才清除对应副本 |
| 确认读取权限被撤销 | 连接级暂停其来源的自动使用；不冒充逐项删除，重新授权后对账 |
| 用户删除某条经验 | 核心建立删除记录，Connector 同步不能自动复活同一目标 |
| 用户要求忘记一个源对象 | binding 标为 excluded；该对象后续修订也不再接收，恢复须用户显式操作 |
| 暂停或移除连接 | 默认停止新增读取，已接收学习继续，经验保留；可明确取消待办、撤回或清理来源 |

来源修订失效使用 reason=source_superseded 的临时来源标记，区别于 user_forget 永久拒收。权威删除的 withdraw/erase 也分别表达；不能用现有内容 fingerprint 的永久忘记来表示普通更新。状态由核心持久化，Connector 不直接管理后端记录。

Connector 来源控制标记保存可查询的 bindingId 和对应指纹。current/pending 更新后，只要早期修订仍有引用或摘录，相关标记就保留。忘记整个对象时，按 bindingId 清点 current/pending 及所有保留标记，不能只清最新两版。无引用且不会重放后才能清标记，不另存旧正文或完整版本库。

guidance 和 lead 均检查来源标记、连接级使用暂停与 sourceFingerprints；线索不能绕过 superseded/withdrawn/erased/user_forget 或撤销访问。其他出口执行各自查看授权，派生经验按根指纹和父修订检查。来源被替代、撤回或确认撤权后，先停止受影响建议，再按剩余独立依据重评；保留的结论仍须满足全部条件，不能直接删除整条多来源经验。

Connector 不能直接覆盖用户编辑。新来源按[冲突与纠正规则](02-experience-model.md#提取与整理)提出修订；普通重复同步不能启用 disabled 或延长复评期限。

正在核实的线索遇到源对象更新、撤回或连接权限变化，下一次定向 recall 必须重新检查，不能因先前缓存是 lead 就转为 guidance。核实当前上下文本身不改来源版本或同步游标。

未完成任务在写入前重新检查 binding 当前/待处理修订及失效标记。uncertain 写按核心恢复规则隔离；不能在源已改变后恢复并发布旧结论。source_superseded 标记仅在全部旧作业终止且无当前经验仍引用后清理；源绑定与临时标记不能按普通完成任务的期限提前丢弃。

标记清理还须确认协议不会把迟到的旧快照重新接收为新修订：无单调版本的推送只能触发重读当前对象。保留经验的解绑会保留仍被引用的精简 source_binding 和来源说明；停止同步不等于可删除所有映射。

## 最小持久化补充

连接配置、游标、source_binding 和作业关联的字段及容量统一见[管理记录合同](07-storage-model.md#管理记录的最小合同)。同步状态不得保存秘密或另建原始材料档案；接收现成经验也遵守 Experience 与 evidence 的容量限制。

来源标记复用管理层标记机制，增加 reason=source_superseded/source_withdrawn/source_erased/user_forget、bindingId 与处理动作；它不写入 Experience.state 的新枚举。用户查看的是正在同步、已接收待学习、部分失败和需要认证，不显示 binding/nonce。

## UI、CLI 与交付

Connectors 页面提供连接添加、来源范围与目标集合选择、频率配置、首轮范围预览、立即同步、暂停/恢复、重新认证和移除。详情分开显示接收与学习进度，并列出失败来源及重试入口。移除默认保留经验，撤回或清理须由用户明确选择。

CLI 提供同等的 list/add/check/sync/pause/resume/status/retry/remove 能力，命令拼写在实现时固定。SDK 提供 Connector 契约和认证批次接收入口，不暴露数据库直写。

ConnectorRuntime、输入合同和管理 UI/CLI 由产品统一提供，EmailConnector、文档目录等各自实现来源协议。P1 验证标准输入，P3 交付连接管理和一个可复现的样例 Connector，P4 再按需增加真实来源。邮件只是一种实现，不进入核心字段。

## 验收案例

| ID | 场景 | 必须结果 |
|---|---|---|
| K01 | 两种不同来源实现相同 Connector 契约 | 不修改 Experience schema 或 LearningCore |
| K02 | 首次回填、重叠窗口、重复页面 | 同源同修订只接收一次，不重复支持 |
| K03 | 页面部分项目落盘失败、接收响应丢失 | 不跳游标；重试复用已确认任务 |
| K04 | 游标已推进但提炼失败/服务重启 | 来源可定位，任务可恢复，UI 不显示已学完 |
| K05 | 一份文档只改一段或恢复先前内容 | 新修订可被接收；不被旧内容忘记标记误伤 |
| K06 | 两个对象有相同文字，只删除其中一个 | 仅处理对应来源归属，核心按剩余证据重评 |
| K07 | 来源删除、权限撤销、临时不可用 | 三种行为可区分；不从滚动窗口缺项推断删除 |
| K08 | 乱序推送与 opaque version | 重取当前快照或按已声明单调序列处理，不按字符串比较版本 |
| K09 | 用户纠正/忘记后再次同步 | 不覆盖用户纠正，不复活排除对象；变更冲突暂缓 |
| K10 | 限流、预算不足与一个高频来源 | 未确认游标不前移，已接收输入保留，其他连接可取得进展 |
| K11 | 暂停/移除连接，Copilot 仍工作 | 核心与代理适配继续可用，默认保留已沉淀经验 |
| K12 | 超长对象、多片段新修订及 pending 冲突 | 超限有明确结果，已确认输入不被覆盖或悄悄截断 |
