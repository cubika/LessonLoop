# 实施与验收

日期：2026-09-14。下文阈值是预先设定的验收目标。部分 [P0 隔离测试](research/2026-09-13-p0/README.md)已完成，完整 P0 验收、真实模型对照和用户收益验证仍在待办中。

本文维护验收 ID、样本规模和发布阈值。[实现质量评估](09-quality-evaluation.md)规定怎样把这些要求做成场景合同、独立判定和执行报告，以及代码提交和发布时如何使用。[首批开发材料](../evals/README.md)已同步并检查完整性；完整场景、独立判定和质量门禁仍待实现，不代表已有产品评测通过。

存储相关条款描述现有 Mem0/Qdrant 原型；[重新选型](research/2026-09-14-memory-selection/README.md)建议采用 Hindsight，尚未迁移。产品行为合同由适配器共用，数据库专用检查随实际后端分别维护，不能用 Mem0 的实现细节判定其他引擎不合格。

## 实施顺序

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| P0 核心与宿主可行切片 | 固定 Mem0/Qdrant/嵌入版本、结构写入与查询、最薄真实 Copilot 插件协议探针 | 尽早验证数据与宿主边界；下表合同通过后才结束 P0，协议探针不代替任务收益 |
| P1 通用经验流程 | 标准接收 API、领域提取、L1–L5、当前修订、guidance/lead 召回与 target 重评、字段查询、查看停用 | 先测生命周期，再用真实模型测提取；不得用 mock 代替质量结论 |
| P2 多层整理 | 变更队列、重复/冲突处理、限定主题跨案例推导、反例、依赖失效 | 高层提炼样本通过，旧父修订与循环支持不能产生可用结论 |
| P3 首版产品交付 | 核心安装包、CLI、Web UI、Copilot plugin 的先核实后采用与刷新、ConnectorRuntime/连接管理与样例 Connector、模型预算 | 完成安装与管理验收，在实际 Copilot 中验证跨任务场景并测量用户收益 |
| P4 真实来源 Connectors | 按需实现邮件、文档目录、笔记/知识库等来源协议 | 通过同步 K01–K12 及来源特有验收，不改核心经验模型 |

首版发布要求 P0–P3；P4 单独交付。P1 能接收直接给出的 L5 不等于 P2 会自动推导 L5。不要为了赶首版把高层提炼只实现为分类标签；也不要承诺全领域的五层自动学习。

## 发布前对照实验与继续投入条件

对照实验属于开发和代码发布前的验证，不是用户日常执行任务的方式。可以在完整 UI 和正式安装包完成前，从源码运行最小核心、真实模型与隔离 Mem0/Qdrant；测试环境仍需要相应依赖。“安装前”指无需先安装正式产品，不表示只检查文档或不运行代码。

对照分为三组：Agent 不增加记忆、使用基础记忆引擎、使用相同引擎上的 LessonLoop 领域层。当前原型的基础引擎是 Mem0；加入 Hindsight 后，对每个引擎分别运行这组比较，再比较完整产品结果。模型、历史材料、工具、起始环境和宿主指令保持一致，各组记忆隔离。基础引擎使用合理的原生配置；人工精选经验只作诊断参考，不代替产品组。具体控制变量和报告要求见[实现质量评估](09-quality-evaluation.md)。

起步可选一段真实且获准使用的历史调查、一个后续相似任务和一个不适用反例。先让两种记忆方案处理历史材料，再让三组 Agent 分别在干净项目副本中执行任务，最后用实际文件结果和测试判定。重复几次用于排查机制和观察方向；正式发布结论仍须满足下文的独立样本与质量门槛，不能把少数演示当成普遍收益。

| 场合 | 执行方式 | 目的 |
|---|---|---|
| 开发及发布前验证 | 在隔离副本中执行三组相同任务，比较质量、错误、步骤、时间和模型成本 | 判断产品是否值得发布及改进哪些环节 |
| 用户日常使用 | 正常执行一次任务，按需召回、核实线索并回传真实结果 | 帮助当前任务，持续纠正或改善经验 |

发布后的普通后台学习不自动复制用户任务跑三组实验，也不静默改变记忆配置来做对照。若以后开展在线实验，需另有明确的用户授权、数据范围和成本设置。日常线索核实、用户纠正及来源更新不是对照实验，不能用这些观察单独声称产品带来了因果收益。

历史材料先形成经验，再执行未参与提炼的后续任务；按时间、来源家族和案例切分，不能用同一案例改写当未见任务。任务应真实执行文件/工具动作，独立判定结果并重复运行。只读 replay、脚本模型、来源子串检查或检索 Precision 均不能证明净任务收益。

测量任务质量、错误、重复调查、用户纠正，同时计入提炼、维护、检索、线索核实与模型成本，分别报告冷启动与多次复用摊销。关闭高层提炼或关闭 lead 的小范围消融用于判断增益来源，不把更多字段、L5 数量当成效果。

最薄宿主探针与核心实验并行，提前验证首次模型输入回填、采用前控制、可信工具材料与纠正回执渠道。合成协议测试只说明通道；实际 Copilot 模型是否正确采用仍需实测。如果真实模型对照没有可靠改善或额外错误上升，先改学习/召回流程，再扩展 UI 和 Connector。

## P0 合同检查

| ID | 必须验证的行为 |
|---|---|
| M01 | 两条经验来自同一批输入，独立条件、来源、层次和 revision 写入后 round-trip 不串字段 |
| M02 | infer:false 不触发默认提取模型；嵌入与向量写入实际发生；无云 Mem0 账号依赖 |
| M03 | 选择性 scope/state/time/level/topic 过滤在候选限额前生效，返回前再验证授权 |
| M04 | 非检索字段的 metadata-only update 成本被记录；检索字段更新由 Gateway 同时改 memory 与 metadata，旧词消失，例外不作正向触发 |
| M05 | add/update/delete 的明确失败与未知结果分别处理；未知操作被隔离，迟到响应不覆盖后续可用版 |
| M06 | Qdrant 管理写先确认，worker 在管理记录、Mem0、完成记录边界终止后不重复写；控制写未知不继续修改经验 |
| M07 | 确认已发写结束后，Qdrant scroll 跨多页导出完整；uncertain 存在时不发布完整快照 |
| M08 | 删除读回不存在，当前经验与短期 job 中复制摘录清理可确认；清理途中不可召回 |
| M09 | 显式 Qdrant provider 与 disableHistory 后，启动/CRUD/重启不产生 SQLite 数据文件；只含 payload 的管理 points 无嵌入持久化 |
| M10 | 固定实际 Node、Mem0、Qdrant JS client/server、嵌入模型与维度，记录启动/重启和资源需求 |
| M11 | [存储模型](07-storage-model.md)字段、必填性、数组与 UTF-8 容量在调用 Mem0 前校验；测边界值/多字节/向量额外占用 |

现有 Mem0/Qdrant 路线的 P0 失败时先记录最小复现与缺口，优先修正网关的完成确认、过滤或扫描能力；不自动引入 SQLite 或第二数据库。更换引擎需按选型结论修订存储合同并重新实测，原有报告不继承为新后端的通过证据。

## 功能验收目录

| ID | 样本 | 应有结果 |
|---|---|---|
| L01 | 混合消息中包含一次任务安排与长期约束 | 只提取持续约束；不漏掉被临时要求包围的有价值内容 |
| L02 | 无用户纠正的调查与来源摘录 | 产生有用发现；不是只保存 agent 总结 |
| L03 | 正常完成、寒暄、没有可复用内容 | 零经验；不是错误 |
| L04 | 用户直接给原则，分别是“采用为我的要求”和“我认为它普遍正确” | 前者可为用户 constraint；后者核验证据，不因 reported 自动 active；均不补造 L1–L4 |
| L05 | 多变量同时变化后成功 | 不能记录唯一原因已成立 |
| L06 | 独立案例、机制证据、共享条件与反例 | 足证正样本产出对应层次；不足的假设默认短期 proposal，仅显式保留且有复评计划才 held |
| L07 | 同一来源重复导入、转发、代理复述 | 不增加卡片或独立支持；不因循环引用而升可信程度 |
| R01 | 中文任务查询英文经验，同义词不含原句 | 可发现相应经验；评测真实模型，不只测固定别名 |
| R02 | 精确错误码/参数名已提取到实体/标识符字段 | Qdrant exact 查询找到语义 top-k 外的记录；未索引正文词不在保证内 |
| R03 | 查询词只在 exceptions，另有对应实际任务 | browse 字段过滤可调查，recall 不接受该字段；实际任务仍检查例外，分词语义须测 |
| R04 | 大量错误 scope/expired/held 记录在前 | 正确筛选不被全局 top-k 挤掉；不得跨范围补足 |
| R05 | 当前条件未确定、经验规则边界 unknown、无相关结果、存储失败 | 合格前者可 lead；后三者不能伪装线索，分别返回明确原因 |
| C01 | schema 生成经验随后添加 legacy 例外 | 内容和索引修订；legacy 任务不再收到旧规则 |
| C02 | 经验 A 支撑 B、B 支撑 C，A 被修订或停用 | B/C 自动建议立即被依赖检查阻止，后台按需重评 |
| C03 | 纠错与检索同时发生、旧写请求迟到 | 按组装边界确定可见性；uncertain 写不被盲重放 |
| C04 | 删除来源含多个复制摘录与未完成作业 | 清除复制位置；后台不能重新生成；清理完成有明确结果 |
| X01 | 手动提交、Copilot 提交同类材料 | 使用相同核心合同；无 eventId/repo 必填项 |
| X02 | 实际 Copilot 新任务自动得到 guidance 或 lead | 验证规划/行动前回填、用途保留、授权核实、采用前刷新；不以 MCP 工具存在代替 |
| X03 | Connector 窗口重叠、源更新、暂停与关闭 | 不重复支持，来源变化重评，已接收学习可继续，核心独立运行 |
| X04 | Copilot plugin 安装、组件加载、两个并行会话与卸载 | hooks/MCP/skills 按固定 CLI 版本加载；共享一个核心写者；卸载不删除经验或中止已接收学习作业 |
| X05 | CLI 提交材料，UI 查询/修订/停用，代理再次召回 | 所有入口看到相同当前状态，权限与删除规则一致；关闭浏览器不停止后台服务 |
| X06 | 在受支持的 Windows 环境安装核心和插件 | 依赖检查明确，启动服务与 UI 无需源码操作；安装错误不报告成功，重启后可恢复使用 |
| D01 | 同一授权集合中的跨 repo 通用经验 | 换 repo 仍可召回；采集 branch 不自动限制适用性 |
| D02 | 明确限定 repo+branch 的步骤 | repo 明确不同则排除；repo 符合但 branch 缺失时可形成具体 lead，不直接 guidance |
| D03 | 只有例外、条件文本与 match 不一致、路径相似前缀 | 例外命中排除；不一致拒绝；不把裸前缀当路径匹配 |
| D04 | 第 4 条 evidence、超过 512 B 摘录或 2 KiB 数组 | 不静默截断；拒绝或重新提炼完整小主张 |
| D05 | 纯派生经验、父修订变化、超过 32 个根指纹 | 引用可用父项；失效不建议；超限不丢来源继续发布 |
| D06 | 16 KiB Experience、4 KiB memory、32 KiB 应用 payload 边界 | 独立检查字节和模型 token 限制；上限不是磁盘占用 |
| D07 | 更广集合发布且去除了私有来源 | 新 proposal 重新判断；不继承 supported/active |

## 召回、核实与反馈完整性验收

|---|---|---|
| T01 | 一条有依据的通用经验在同一授权集合的项目 B 中缺文件类型 | includeLeads=true 返回 lead+具体缺口；经验 state/revision 不变 |
| T02 | 核实确定条件成立，所有例外排除 | 真实 contextEvidence+target 重评返回 guidance；不提升 assessment 或写入来源计数 |

| T10 | 当前任务不适用 / 新例外 / 主张反例 / 单次成功 | 分别不改记录、提交补证重评、按实质证据暂停/修订、不得自动全局验证 |

| T13 | 私有项目材料与通用集合经验 | 可在授权范围判断当前适用性；不得自动跨scope保存补证或扩大经验范围 |
| T14 | 删除明确由用户发起 / 仅Agent得出本次不适用 | 前者现有删除流程，后者没有删除权限或副作用 |

| ID | 场景 | 必须结果 |
|---|---|---|

| U04 | 旧任务响应迟到、请求超时/取消、同任务新请求已替代旧请求 | 旧响应不注入当前上下文，不覆盖新结果 |

| U07 | 暂停前目标变版、歧义目标、普通代理冒领用户原话 | 不误暂停新版本或多条经验，不报告未确认暂停 |

| U09 | 快速同步完成、较慢后台完成、重复状态查询 | 快速合并最终一次；慢任务更新原状态；不重复通知 |
| U10 | 生效结果之后被修订、撤回、权限改变或状态查询失败 | 当前 receipt 不复用历史 completed 宣称有效，不泄露隐藏内容 |
| U11 | 插件会话/UI 关闭、服务重启、作业结果过期 | 已接收任务可继续，结果在保留期内可查；不启动 Agent 补通知，不伪造历史 |
| U12 | 文本/向量或索引字段未完成、写回执丢失 | 不报 effective，先按恢复合同核实；可召回不等于任意查询必命中 |

## 准入与验证专项验收

| ID | 成对样本或触发 | 必须结果 |
|---|---|---|
| A01 | “这次简短” / “以后我的总结简短” | 前者不长期入库，后者可为真实用户 constraint；一次例外不覆盖长期偏好 |
| A02 | “本周试点用 X” / “先临时这样做” | 前者后续用途明确且有可解析边界才限期保存；后者不凭 TTL 自动变经验 |

| A05 | 外部第一人称模板与本人真实偏好相冲突 | 模板不冒领 constraint，不覆盖/暂停本人偏好；真实事实冲突仍核对 |
| A06 | 无用途猜测 / 显式保留且有用途的未定假设 / 已被否定的新主张 | 依次为 reject、supportAdequate=unknown 的 hypothesis/held+review、fail/reject；不得全部丢入 held |
| A07 | held 到期、重复输入、用户补证与旧到期任务竞争 | 到期停用，重试不续期；旧任务不误停已补证的新修订 |
| A08 | 同 scope 补证、越 scope 补证、目标 revision 已变 | 有授权才关联；陈旧结果不激活新版，可作为普通新材料检查 |
| A09 | review.question 包含可执行文本、宿主没有执行授权 | 核心不执行，也不凭补证需求扩大权限 |
| A10 | 同模型复核、helpful、重复转载或反复召回 | 不增加外部支持，不自动 supported 或延长有效期 |
| A11 | 正确但无新增价值的完成消息 / 少见且代价大的有效发现 | 前者 reject，后者可通过价值门槛，不按频次单独决定 |
| A12 | recall 返回用户 attributed 约束与 supported 事实 | 同时返回 purpose/basis/assessment/有效期，消费方能区分；不省略标签凑预算 |
| A13 | 输入已接收但提取失败 / 提取成功零有价值输出 | 前者显示失败待处理，后者显示未形成经验；不混称“已记住” |

Connector 另执行[同步验收 K01–K12](08-connectors.md)：部分接收失败、响应丢失、乱序、同文字不同来源、配置变更重扫及游标/学习进度分离均须覆盖。样例测试不代表所有真实来源已支持。

## 质量样本与发布门槛

先建立 60 个真实或经用户确认的脱敏学习机会：包含有价值发现、混合约束、一次性请求、无学习价值、冲突和反例；预留至少 20 个不参与提示词调整的样本。再建立 40 个后续查询，其中包含无关任务、精确实体、跨语言与排除条件。多层整理另设至少 12 组案例，区分陈述、关联、机制与迁移。人工标签和样本来源须可追溯。

多层整理的 12 组按层次与证据充分性预先标注，其中至少 4 组有足够机制或迁移依据，要求自动产出有支持的 L3/L5，覆盖两个层次；另设应保留假设和应拒绝泛化的负样本。逐层报告应产出案例的覆盖，初始门槛 75%，不能用全部 held 或低层输出抵充。所有产出要求依赖绑定正确、关键条件完整；保留至少 4 个未参与提炼的晚期任务检查迁移，其中至少 3 个正确使用、错误扩大范围为 0。这里验收限定主题中的实际五层能力，不推断全领域有效。

专项样本中临时性、规范/事实、支持充分性、值得保留与后续收益分别标注。不受来源支持的 active、临时指令误入长期规则、普通重复导致自动启用等已知边界要求为 0；同时报告拒绝后的重要经验遗漏，不能靠全拒获得表面准确率。

模型输出不能同时充当唯一评委。两位独立评审者判断有价值的经验和改变行动的条件；分歧保留并仲裁。开发中的代理评审可找设计问题，不能替代真实用户标签。小样本结果附分子/分母与不确定性，不只给百分数。

| 指标 | 初始退出门槛 |
|---|---|
| 值得保留的输出比例 | 至少 85%；含 active 与新增 held，单独标注需实质重写及无后续用途条目 |
| 重要经验覆盖 | 至少 80%；漏学分为采集漏、提取漏、拒绝保留、召回漏 |
| 行动条件/例外完整率 | 至少 95%；冻结高风险反例不得丢失关键限制 |
| 不受来源支持的事实/因果断言 | 冻结对抗样本为 0；本人要求另标不当事实证明，所有普通样本均报告 |
| 临时要求误保存及待复评积压 | 专项误保存为 0；报告 held 到期处理覆盖与新增噪声，不把移到 disabled 当提炼准确率提高 |
| Precision@3 | 至少 0.85；guidance 按正确采用评判，lead 按值得核实且缺口正确评判；分别报分子/分母 |
| Recall@3 | 至少 0.80；按最多3个标注核心目标计算，分开报告可采用召回与线索召回，避免全拒或全变lead作弊 |
| 正确不建议 | 无关/排除条件样本至少 90%；已知资格失效对guidance/lead均为零绕过 |
| 线索核实收益与成本 | 报告从lead到正确guidance比例、无效检查次数与耗时；T02完整路径必须通过，不能以全部未确定替代 |
| 错 scope、撤回后投递、已知旧版投递 | 冻结回归集为 0，任何一例阻断发布 |

数字是准备评测时冻结的起点，若样本使目标不合理，应在运行前说明原因修改，不能看完结果再降低门槛。这些阈值不意味着一般化的准确率保证。

## 后续任务收益

选择至少 20 对后续任务，用相同起始材料、模型、宿主设置和 token 预算比较“未提供 LessonLoop 经验”与“提供经验”。保留原有项目指令与宿主原生记忆条件，避免人为削弱基线。随机顺序或交叉分配，评分者尽量不知道条件。

记录重复调查步骤、用户重复纠正次数、完成质量和新增错误，并计入由线索引起的额外检查。仅提高线索数但增加总工作量不算收益；无新信息的循环、错误采用和跨任务污染单独报告。首个试用退出条件：至少一半任务有可核实的重复工作减少，不得出现由错误范围、过时建议或丢失例外造成的新严重错误；其他质量指标不得明显恶化。样本太少时只报告有限效果，不声称统计证明长期收益。

跨案例抽象采用时间切分：较早材料提炼，较晚任务验证；反例不能先作为训练来源又充当独立成功测试。主要基线是相同宿主与项目配置下未提供 LessonLoop 经验的任务表现。

## 性能、成本和增长

在声明的 Windows 硬件上先测 1,000 与 10,000 条经验，记录 cold/warm、正确结果和失败样本。拟定起点：材料接收本地附加 P95 20 ms；不含远程 reranker 的温热 recall P95 500 ms、P99 1 s；模型额度可用时提交至可检索 P95 120 s。Copilot 自动回填设置硬 deadline，超时不阻塞宿主继续工作并记录退化。具体 deadline 在 P0 安装测量后冻结。

同时记录每百次提交/每次整理的模型调用与 token、嵌入次数、metadata 编辑重嵌入成本、存储大小、待处理最老作业年龄和 Qdrant 索引构建耗时。不能只报告成功请求延迟；不以删除困难样本或任意卡库容量掩盖增长问题。

在 10,000 条通过后再测 100,000 条、混合读写和长时间运行。1,000,000 条属于后续容量研究，不是首版发布承诺。规模测试要固定相关案例，增加无关、重复、过期和跨范围数据，观察精度与维护进度是否下降。

## 阶段交付记录

每阶段保留版本清单、运行命令、通过/失败数和已知限制。文档或静态类型测试通过，只证明对应层面；模型质量、宿主自动回填和生产容量必须各自有实际证据。

每项实现关联本页验收 ID、场景 ID、测试入口和结果。报告分别表达运行是否完成、质量是否达标；必测项缺少依赖、标签或结果时不能通过。硬合同失败、未测事项和统计指标按[评估状态与退出码](09-quality-evaluation.md#评估状态与退出码)处理。
