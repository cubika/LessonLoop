# 工作结果与效果回顾

日期：2026-09-15。任务反馈保存当前结果及其来源，周期回顾、问题提醒与开发导出读取同一记录。完整效果场景进度见[13](13-implementation-plan.md)。

## 四个独立设置

| 设置 | 作用 |
|---|---|
| 工作学习 | 获准材料、动作和结果形成WorkView，触发复盘与方法更新 |
| 方法自动推荐 | 新任务自动搜索并准备方法；关闭后仍可显式使用 |
| 效果回顾 | 记录方法投递、任务结果和用户评价，生成周期回顾 |
| 回顾提醒 | 控制本地通知，静音不停止学习或统计 |

学习和回顾分别控制scope及来源范围。只开回顾不能自动把材料用于长期学习，关闭回顾也不会停止独立开启的方法进化。

停止学习后不再摄取新材料或建立新自动复盘，已可靠接收作业默认完成，用户可显式取消。停止推荐不删除方法。清空效果数据不等于忘记学习来源；两种操作在UI分别表达。

## 结果进入学习与回顾的两条路径

工作学习接收真实新尝试、观察、结果、反例和用户原话，既包括使用方法后的任务，也包括没有使用任何方法的探索。CaseBuilder形成WorkView，学习器按02产生新经验或方法变更。

效果回顾记录宿主投递、任务结果和用户评价。只开回顾时，Copilot原始观察进入独立的持久结果判断队列，不创建学习来源或Hindsight bank。学习开启时，工具原始观察仍可用于学习、经验条件核验和排错，不与方法步骤匹配以推断采用。AI判断、周报和模型自评不能成为独立支持，同一事件进入两个通道也不增加案例独立性。

方法发生变化必须由真实材料支撑，常规复用通常不改版。已有关键依据被否定时先走产品暂停控制，再更新方法；效果报告不能直接改写方法状态。

## 能观察到什么

| 环节 | 可确认的事实 | 保留的限制 |
|---|---|---|
| 任务开始/结束 | 可信宿主的真实任务身份和停止信号 | 结束不是成功，未观察到结束不虚构时间 |
| 核心返回 | 任务与方法版本的关联 | 返回不等于已注入Agent上下文 |
| 宿主投递 | 实际回填与对应响应关联 | 投递不证明Agent采用 |
| 结果 | 有依据的任务结果 | 宿主停止、超时、工具成功和Agent完成声明都不自动确定任务结果 |
| 评价 | 用户对某个方法版本的评价 | 有帮助与任务成功分别记录 |
| 方法修订 | 新版本改变了哪些步骤及其依据 | 版本次数不等于质量提升 |

每个任务保存当前结果，各方法版本分别保存投递和评价。Copilot以整个会话为结果范围，AI判断需引用原始观察；人工可以确认或纠正：

```json
{
  "id": "task-123",
  "revision": 4,
  "taskOutcome": "succeeded",
  "outcomeText": "产物检查通过",
  "outcomeSource": "ai",
  "outcomeScope": "session",
  "outcomeAssessment": "completed",
  "outcomeEvidence": [{"role": "tool", "excerpt": "输出文件读回检查通过。"}],
  "feedback": [{
    "playbookId": "generated-file-editing",
    "revision": 3,
    "delivered": true,
    "userRating": "helpful",
    "ratingText": ""
  }]
}
```

投递未确认时delivered为null，结果缺失时taskOutcome为unknown，没有用户评价时userRating为null。字段独立更新，写入检查当前revision；同值重试不增加记录，旧请求不能覆盖新值。无方法任务也保留结果。

| AI结果 | 所需依据 |
|---|---|
| succeeded | 用户明确确认完成，或工具观察确实验证了用户要求的结果；Agent自报完成不足以确认 |
| failed | 未恢复的错误使请求目标仍未完成；先报错、后成功修复不算失败 |
| abandoned | 用户明确取消或放弃这项任务；暂停生成、退出或断线本身不够 |
| unknown | 目标或结果依据不足，或仍有采集缺口 |

agentStop/sessionEnd触发后台判断，宿主停止原因只作为观察。超时和工具错误也不直接决定任务结果。新材料会重新判断尚未人工确认的AI结果；采集缺口及恢复规则见[07](07-storage-model.md)。判断服务的pending/unavailable单独显示，模型调用失败不记为任务failed。

效果卡显示“AI判断（待人工确认）”“宿主报告”或“人工确认或纠正”。有scope权限的用户可确认当前值，也可在“填写或纠正结果”选择四种状态并补充说明。保存后刷新汇总和问题复核；修订冲突保留草稿，加载最新记录并核对后才能再次保存。人工填写的unknown同样受保护，后续AI和宿主写入不能覆盖。

任务结束后停止获取方法，保留期内可以更新已登记的反馈。更新不会自动创建记录，过期或清空后旧请求不能恢复正文。

## 方法变化与案例

| 回顾项 | 入选依据 |
|---|---|
| 方法变化 | 有新Playbook修订，具体增加/改变步骤、分支、例外或停用原因 |
| good：用户确认有帮助 | 真实用户评价能关联任务和方法，仍分别显示实际结果是否可见 |
| bad：确认产品问题 | 错范围、失效版本投递、错误回执或越过决策边界等有具体证据 |
| bad：用户报告问题 | 误导、返工等反馈明确，未确认原因保持未知 |
| 待核实 | 仅Agent自评、疑似漏用、缺结果或关联不完整 |

方法详情展示前后变化和当前做法，使用视图展示一次使用或问题。WorkView是学习输入，两者可引用同一真实事件，但不能相互复制摘要作为新证据。

用户可复核案例分类、补充真实材料、关联已知问题、查看当前方法或发起纠正。分类变更不自动变成知识支持。缺少某类案例就少展示，不补造正例。

## 周期与通知

默认每7天生成一次本地回顾，最多3项方法变化、3个good、3个bad和2个待核实问题。可调整周期；无新内容不推送空提醒。离线多个周期后合并覆盖区间，说明缺口，不补发一串通知。

通知只说明回顾或问题可查看，预览不包含私有任务正文。普通方法更新留在方法库；严重且已确认的范围/旧版违规在服务和通道可用时以5分钟内提示为初始目标。同问题去重并保留影响任务数，疑似升级为确认严重时可额外通知一次。

模型、采集或通知失败不得阻塞原任务。失败与没有案例分开显示，重启或重复调度不重复通知。发送前重查范围、期限、开关与去重状态。后台不启动新Agent伪造聊天回执。

## 统计口径

报告保留的任务数、确认投递的任务数、成功/失败/放弃/未知的任务数，以及有帮助和有问题的用户反馈。结果来源另列AI判断、人工确认或纠正、宿主报告及来源未记录，AI结果不能冒充人工确认。总览和周期回顾使用同一口径；更正结果或评价后旧值不再参与计数。不给出方法成功率或自动采用率。

统计可以描述方法被怎样使用、哪里出问题，不能从一次成功、引用率或前后周报直接推出节省时间和因果改善。用户估计单列。官方插件已有使用和诊断日志，可复用实际含义相符的字段，不把它们升级为任务效果证据。

## 保留、删除与开发导出

保留期和预算见[07](07-storage-model.md)。关闭回顾停止新写入和待处理判断，已完成反馈保留。来源擦除会清理关联判断材料和受影响的AI引用；清空回顾保留递增版本的空标记并清理队列，过期后整体删除。问题复核引用记录revision；事实更正后需要重新确认。

用户选择案例并审阅脱敏范围后可导出开发样本。导出保留已知输入、方法修订、真实轨迹与缺项，没有初态或工具结果就标不完整。导出不自动上传、建issue、发消息或启动开发Agent。

进入开发回归后补独立判定器和相近反例，按[09](09-quality-evaluation.md)划分数据；已用于调试的案例不能再作未见测试。生产任务始终执行一次，线上随机实验需单独设计和授权。

## 验收范围

效果回顾由P3交付，MTH12及O01–O12检查路由、真实性、生命周期和通知。P1/P2的工作学习不依赖回顾功能完成。回顾通过只说明观察和展示符合合同，不表示已经证明产品净收益。
