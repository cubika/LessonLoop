# 自动复盘与方法学习

日期：2026-09-15。状态：当前领域设计，已有学习与演进实现，完整分层质量尚未验收；进度见[13](13-implementation-plan.md)。本页定义语义；字段、容量和保留期统一由[07](07-storage-model.md)维护。

## 领域对象

| 对象 | 含义 | 与其他对象的关系 |
|---|---|---|
| Source | 获准使用的原文片段、工作事件及来源归属 | 每个片段有稳定身份，可查看、补充结果、撤回或擦除 |
| Experience | 一个可独立解释和修订的主张 | 具有 L1–L5 层次、依据及边界，支持方法或其他经验 |
| Playbook | 面向任务的步骤、分支、完成检查和停止条件 | 引用 Experience；不是多条事实简单拼接，也不等同 L5 |

对外只维护 Source、Experience、Playbook 三类资源。WorkCase 是后台整理目标、尝试、观察和结果的内部缓存；查看 Source、Experience 或 Playbook 时按需展开相关工作视图。EffectCase 从已保存的任务事件与用户评价生成使用视图。两种视图都不要求用户创建或维护独立案例。

内部仍保存原始来源、任务归属、顺序、使用的 Playbook 修订和用户纠正。视图可以重建，关联不能依赖每次生成的摘要。LearningJob 表示处理状态，完成可以零产出。现有 Material 和 Method 存储名称保留在核心内部，公开 API 分别使用 Source 片段身份和 Playbook 名称。

方法可以由不同层次的经验支撑，一次有价值的发现也可形成局部做法。首版 Playbook 不递归调用其他 Playbook；比较旧方法可帮助产生新经验，但方法沿革本身不增加独立支持。

## 分层提炼流程

| 层次 | 处理工作 | 预期产物 | 必须保留的边界 |
|---|---|---|---|
| L1 经历 | 从真实材料中识别关键动作、观察和结果 | “重新生成覆盖了手工变更”等事实或当事人陈述 | 区分观察、原话和推测，不能只保留最终总结 |
| L2 关联 | 比较不同案例的信号、行为和结果 | 哪些现象共同出现、哪些调查经常无效 | 共同来源、样本范围与不一致案例；共现不等于因果 |
| L3 解释 | 结合机制线索分析原因，比较替代解释 | 步骤为何有效或失败、还需检查什么 | 无法排除的解释明确标为假设 |
| L4 条件模式 | 比较适用与不适用案例，整理判断顺序与分支 | 在什么条件下采用哪种做法，以及例外 | 不抹平条件差异，不以一个成功案例泛化所有环境 |
| L5 原则 | 比较不同对象或方法中的共同决策方式 | 可用于新场景的原则或思考模型 | 迁移范围与后来发现的反例；通用措辞不等于迁移能力 |

系统按问题和材料选择处理路径，可跳层、并行产出或零输出。每次必须生成五层、把原生 observation 当作 L4、把 mental model 当作 L5，均不符合本模型。层次、依据与任务适用性分别判断。

Hindsight 的提取、因果链接、归纳和综合能力用于上述工作。LearningService 组织主题、输入与候选，方法组装将合格经验变成可使用结构；不再运行一套内容相同的基础提取。

## 从工作到方法

1. 整理 WorkCase：记录目标、约束、关键尝试、结果和未解决问题，保留真实来源与采集缺口。
2. 检索同一授权范围内相关案例、经验和方法，判断本次有何新增信息。
3. 执行需要的分层提炼。相关原生产物作为候选，不自动取得产品发布资格。
4. 组装新方法或提出具体变化：步骤顺序、判断分支、完成检查、例外、拆分或停用。
5. 校验依据、全局条件、步骤路径和用户控制，通过后发布新修订及变更说明。

任务结束只是触发时机之一。失败、放弃、部分完成或阶段性调查也可复盘；普通完成消息没有新增价值时不形成经验。自动复盘不重跑真实任务，不自动联网或执行验证命令。

## 准入：先判断是否该记，再判断能否用

| 输入性质 | 处理 |
|---|---|
| 一次性要求、进度、普通完成 | 默认不作为长期经验，不覆盖现有持续要求 |
| 用户持续偏好或有权设置的规范 | 保留真实原话、范围和期限，可作为 attributed constraint |
| 客观事实、工具行为、方法效果 | 检查对象、版本和相应资料或观察；用户自信不等于事实已验证 |
| 原因解释或一般原则 | 检查机制、支持范围和反例；证据不足保持假设 |
| 重复转载、Agent 复述、模型互审 | 可辅助发现问题，不增加独立证据 |
| 无依据但明确要求保留的思路 | 只有有后续用途、范围完整且有具体复评问题时才进入 held |

每个候选分别检查后续用途、新增价值、范围完整性和支持充分性。任何一项失败不能被“很有用”抵消。支持充分时可发布；被否定的主张拒绝；支持未知的普通候选留在短期作业，不建立永久候选堆积。

本人要求与事实解释可拆开。例如“我选择 X，因为它永远更快”，前半可为约束，后半仍需依据。外部第一人称材料不能冒领本人偏好，单次例外不会改写长期规则。

## 发布状态、依据与适用性

| 维度 | 语义 |
|---|---|
| basis | reported、observed、inferred，说明陈述、观察或推导来源 |
| assessment | attributed、supported、hypothesis、contested，说明主张依据状况 |
| state | active 可参与自动使用；held 等待指定复评；disabled 停止使用 |
| applicability | general、conditional、unknown，说明记录本身边界是否明确 |
| taskApplicability | applicable、not_applicable、undetermined，只描述本次任务 |

active 的 Experience 必须有充分支持，或是有可信本人原话的合法持续约束。Playbook 的活动资格取决于自身边界、所有支持经验的当前资格、有效期和用户控制；没有单一分数可以抵消失效来源。

held 必须有原因、具体问题和复评期限。新材料可触发复评，重复输入、等待或使用次数不延长期限；到期仍未解决则 disabled。主动重新开启需重新准入。有效期到达立即停止投递，不等后台修改状态。

## 方法的结构与使用语义

方法具有全局条件和例外，步骤可包含完成后才能判断的分支。支持经验的发布资格与本次分支条件分开：互斥分支不要求同时成立。

准备方法时核对当前发布资格，并一次返回完整条件、步骤、分支和检查。工作 Agent 核实全局条件，执行诊断，再根据本轮结果选择路径；无匹配、多匹配或尚不确定时继续调查或询问，不猜默认路径。步骤不授予超出当前任务的权限。

方法返回 guidance 表示完整指导已提供，本次适用性由工作 Agent 判断。服务不再逐步批准分支，也不把返回方法视为已经执行。没有适合的方法时正常工作；本次跳过不会删除其他场景仍可用的方法。直接经验召回仍可返回 lead，提示待核实的经验条件。

## 方法怎样进化

| 新发现 | 处理方式 |
|---|---|
| 正常复用，没有新增信息 | 可记录使用，不改方法、不增加主张支持 |
| 遗漏前提或例外 | 增加条件或分支，说明改变哪些步骤及其来源 |
| 更好的排查顺序 | 比较实际尝试与结果，调整顺序并保留适用范围 |
| 不同场景需要不同做法 | 拆成有明确范围的方法，保留沿革和各自依据 |
| 新证据否定关键步骤 | 先暂停受影响方法，再修订或停用 |
| 用户改变持续要求 | 按真实意图修订，普通自动学习不覆盖用户控制 |

方法变化必须有实质内容，更新标题、换措辞或增加 level 标签不算方法进化。失败结果不会自动证明方法错误，成功也不会自动证明方法造成改善。系统可提出待核实问题，不补造原因。

## 来源、依赖与长期支持

来源保留真实角色、连续原文、发生时间或位置，以及用于去重和失效传播的指纹。缺失信息保持缺失。不同 caseId、不同转载地址和多次推导不证明来源独立。

Experience 可以引用原文或有效的父经验修订，引用图禁止循环。Playbook 只引用合格的 Experience；条件和理由中新增的事实须有依据。父修订变化、来源撤回或用户停用后，依赖项在重新核对前不再投递。

WorkCase 和完整材料有保留期限。发布长期经验时保存获准的必要短证据，方法引用该经验；不能只依赖将过期的案例链接。禁止复制或已到期的依据不得延长保存，相应方法停止使用。保留和清理统一见[07](07-storage-model.md#保留与删除)。

## 结果回流与工作权限

工作学习开启且来源获准时，新动作、结果和反例可以自动进入 WorkCase，触发后续提炼。效果回顾使用另一套有期限的统计记录；周报、自动标签和模型自评不重新成为证据。学习、推荐、回顾和通知分别控制，具体路由见[11](11-post-release-evaluation.md)。

产品只能核实已提交或宿主在原任务权限内取得的材料。review 问题、方法步骤、外部文件和导出 Skill 都不能增加授权。跨范围发布需要明确目标与脱敏，不继承私有来源的使用资格。
