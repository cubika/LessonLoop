# 经验模型与学习规则

日期：2026-09-14。状态：待实施的领域规则。本文定义经验的含义、准入和生命周期；请求与响应见[接口合同](04-contracts-and-extensions.md)，字段、容量及保留期限见[数据模型](07-storage-model.md)。

## 三个概念

Material 是代理适配、Connector 或用户提交的材料，包含原文、来源归属和必要上下文，按输入保留期保存。Experience 是可独立解释和修订的经验。LearningJob 负责在后台处理材料；它的身份只用于作业管理，不参与经验有效性判断或用户检索。

经验保留必要的来源摘录，来源不必有系统原生 ID。`id` 和一个 `revision` 用于编辑、停用、引用及排除过时结果。作业身份用于进度和恢复，来源位置则供用户查看原件。

## 抽象层次

| 层次 | 回答的问题 | 成立条件与示例 |
|---|---|---|
| L1 事实经验 | 观察或明确陈述了什么 | “这次生成步骤覆盖了手工修改。”引用输出或当事人陈述，并区分两者 |
| L2 关联经验 | 哪些现象在观察中一起变化 | “这些样本中，扫描数据增加时延迟也增加。”写明样本范围；不宣称因果 |
| L3 因果解释 | 什么机制可能解释结果 | “执行计划显示未利用分区裁剪，额外扫描增加耗时。”证据须支持机制；排除不了替代解释则仍是假设 |
| L4 条件模式 | 什么条件下会重复出现 | 比较案例后提出“生成产物的手工变更会在再生成时丢失”，限定确实被覆盖的生成方式和例外 |
| L5 原则或模型 | 什么能迁移到其他决策 | “改变生成结果前先找到生成源”，保留机制、适用限制和迁移验证范围 |

L1–L5 描述抽象层次，没有逐级晋升要求，也不给高层经验默认排序奖励。L1 可能比 L5 更可靠。用户直接提供原则时可以标为 L5，无需补造低层事实；自动推导也可以跳过层次或不产出经验。

L2 要验证共同变化，L3 要检查机制解释，L4 要比较跨案例模式，三者分别评测。操作成功不能单独确定原因，转载次数不能充当案例数量，把具体名词换成通用说法也不算完成迁移。

## 经验怎样表达

模型提出内容 proposal，服务负责校验并设置受信字段。模型输出不能直接决定存储状态。

| 字段组 | 含义 | 设置责任 |
|---|---|---|
| 身份与归属 | `id`、`revision`、`scopeId` 标识可管理的经验及授权集合 | 服务维护稳定产品 ID 和领域修订；后端原生 ID 单独映射 |
| 主张与分类 | `conclusion`、`level`、`purpose`、`topics`、`entities` 表达一个主要主张及查询入口 | 模型提出内容，服务校验 |
| 适用边界 | `applicability`、`conditions`、`exceptions`、有效区间说明何时可用 | 模型提出边界，服务核对；采集项目不自动成为限制 |
| 依据与判断 | `basis`、`assessment`、`evidence` 区分陈述、观察和推断及其支持程度 | 真实来源由接入通道绑定，服务执行准入策略 |
| 推导与来源 | `derivedFrom` 绑定父经验修订，`sourceFingerprints` 继承根来源 | 服务核验依赖和来源；重复指纹不增加独立支持 |
| 使用与复评 | `state`、`review` 区分可用、暂缓和停用 | 服务按下文生命周期处理，用户可纠正或停用 |

字段枚举、必填性与字节限制统一见[Experience 字段契约](07-storage-model.md#experience-字段契约)。可替换实现须保持稳定产品身份，不能因引擎重处理更换 ID 而丢失停用和纠正记录。已删除的 Mem0 原型曾直接使用厂商 ID，该约定只保留在历史设计中。

`supported` 表示已有依据支持记录中的结论和条件，仍可能因环境变化而失效。`reported`、`observed`、`inferred` 分别表示陈述、观察和推导，仅说明依据的性质。即便确认是用户原话，客观断言仍需核实。

确认没有额外任务限制后才能设为 general，空条件并不足以支持这个判断。conditional 可以只有例外，L5 也可能是 conditional。采集时的 repo/branch 先作为来源上下文，结论确实依赖它们时才写入条件。

`active` 表示已通过准入，使用时仍检查授权、适用性和有效期。`held` 用于暂停已有经验，或保留用户明确选择的少量待验证假设；未通过准入的 proposal 不会一律进入 held。`disabled` 表示停用，删除另走清理流程。

“已接收”“旧建议已暂停”“新规则已生效”描述服务处理进度，不增加经验状态，详见[接口与回执](04-contracts-and-extensions.md)。用户确认可以确定本人偏好或有权设置的要求，事实与因果仍按证据判断。

一条经验只写一个主要主张，方便单独修订。彼此独立的事实和流程分开保存，不建立逐句证明 DSL。层次、用途、主题、实体、依据、判定等任何领域字段改变，都会产生新 revision；创建时间不变，更新时间随修订变化。重建索引或更换作业 nonce 不改变 revision。

## 准入：先判断是否该记，再判断能否用

提取时先拆开消息中的独立主张，再判断持续意图、内容性质、范围和价值。当前任务要求由宿主执行，是否长期保存另行判断。不能只匹配关键词：转述、引用、条件句和后文例外都要一起理解。

| 输入及例子 | 判定依据 | 持久化与使用结果 |
|---|---|---|
| 一次性要求：“这次先用 npm” | 明确限定当前任务，无后续用途 | 不创建 Experience；不覆盖已存 pnpm 规则，当前任务由宿主处理例外 |
| 有期限的跨任务约定：“本周试点都用 X” | 真实用户、明确期限和后续用途 | 经价值检查可 active；存 validUntil/明确可判断的终止条件，到期停止召回 |
| 持续偏好：“以后我的总结尽量简短” | 真实本人在表达偏好，适用对象明确 | purpose=constraint，reported + attributed；可 active，不需要实验验证喜好 |
| 有权设置的要求：“这个项目统一用 pnpm” | 确认是制定要求而非描述事实，且调用身份可设置该范围 | purpose=constraint，reported + attributed；可 active，保留例外与范围 |
| 事实：“项目现在使用 pnpm”或“接口最多 100 条” | 是对客观情况的描述，需要当前配置、正式资料或相关观察支持 | 不因用户自信就激活；支持充分为 supported/active，否则提取保留在短期作业 |
| 原因：“这次失败肯定是缓存” | 原话是解释，证据是否支持该机制并区分替代解释 | 不直接激活；保留有依据的观察，原因作为 hypothesis proposal |
| 原则或流程：“超时就重试一定安全” | 检查前提、副作用、反例及支持范围 | 不能因表述通用或标成 L5 激活；证据与适用范围均足够才 supported/active |
| “记住这个结论”但结论未验证 | 明确保存意图，不代表事实确认 | 仅在用途明确且有具体复评问题时建立 held；否则说明未形成可用经验 |

`purpose=constraint` 专指真实用户为本人或有权管理的范围设定的要求，包括本人偏好。“某文档规定如此”应按 fact/procedure 等用途处理，并检查该来源是否有权规定此事。命令式句子本身不能取得 constraint 身份。

用户不能替其他人设置偏好。提炼器也不能把“这更快”改成“我偏好它”来跳过事实核验；同一句话里同时包含个人选择和事实解释时，可以拆成两条主张。

持续意图不明确时，默认不写成长期规则。歧义会影响重要后续行为时才简短澄清一次，无需逐条审批。明确的限期跨任务规则可以保存；单次任务要求即使设置到期时间，也未必有保留价值。“直到迁移结束”等边界若无法判断，必须保留这种不确定性，不能当作永久有效。

外部模板或建议与本人偏好不同，不会让已确认的偏好进入 held。用户改主意时再按真实意图修订。来源撤回、本人纠正或适用范围不明仍会触发复评；客观事实有矛盾时，始终按证据判断。

## 价值筛选与可执行判定

所有新增经验都要通过后续用途、新增价值和范围完整性检查。证据充分性再决定能否 active，或是否仅允许用户显式保留为 held。各项分别判断，不用一个总分抵消某项缺失：

1. 后续用途明确：能说明何种未来任务会少做调查、少犯相同错误，或需要遵守何种持续约定。一次少见但代价大的发现也可通过，不要求先重复多次。
2. 内容有新增价值：不是进度、普通完成、无新增信息的重复或既有规则改写。同源多次输入不增加价值或独立支持。
3. 主张与范围完整：一个主要结论，保留会改变行动的条件/例外，能在预算内完整表达；抽象不得扩大证据覆盖。
4. 证据支持到哪一步：本人偏好依据本人原话，事实依据相应资料或观察，推导依据机制与案例。充分为 pass，尚无法确认或排除为 unknown，已否定/来源伪造为 fail；“很有用”不能使 unknown/fail 变成 pass。

提取作业短期保存 admissionDecision，记录内容性质、持续性、后续用途、检查结果、处置和简短原因，不保存模型长推理或长期评分。处置取 reject/merge/retain_active/retain_held。无价值的内容直接 reject，不留给用户清理。模型可以建议处置，服务核对来源、类型、范围、期限和状态组合后才写入。

新增 retain_active 必须满足 supportAdequate=pass。retain_held 只接受 supportAdequate=unknown，且后续用途、新增价值和范围完整性都通过，用户明确要求保留，并有 review 计划。

supportAdequate=fail 的新主张不能因一句“记住”而进入 held，但可以另行提炼有依据的纠错发现。已有经验遇到矛盾材料时可以先 held 核对；确认错误后转为 disabled。

active 允许两类记录：通过上述检查的 supported 经验；或真实用户本人偏好、有权设置的要求，满足 purpose=constraint、basis=reported、assessment=attributed，并保留对应的可信用户摘录。外部 attributed 事实、hypothesis、contested 不得自动作为确定指导。每次召回仍检查 scope 权限、applicability 和来源有效性。

## 怎么验证

| 验证对象 | 最低应检查的证据 | 不能据此声称什么 |
|---|---|---|
| 原文与归属 | 摘录确实来自实际材料，角色由可信通道决定 | 引文真实不证明内容真实 |
| 偏好/规范性要求 | 用户确实在表达意图，有权设定该范围，期限及例外完整 | 不证明配套的性能/因果解释 |
| 客观事实 | 对象/版本一致的配置、正式资料或实际观察，与断言直接相关 | 一次观察不证明任何环境都成立 |
| 方法/流程 | 实际前提、步骤与结果，覆盖会影响结论的例外 | 测试成功不等于全场景保证 |
| 因果解释 | 机制证据，或有区分力的比较/干预；明确尚未排除的其他解释 | 先后发生、重复成功或模型共识不等于唯一原因 |
| 跨案例模式/原则 | 独立案例、共同条件、反例检索及未参与提炼任务的迁移表现 | L5 标签、记录数量不等于经过迁移验证 |

核心先检查已提交且获准使用的材料。缺信息时提出具体问题，由宿主在当前任务权限内决定是否读取配置、查资料或运行测试。核心不自动联网、执行命令，也不从 review.question 取得授权。

经验主张的补证通过 submitMaterial.verificationFor 绑定同 scope 内已授权的 ID 和 revision，保留实际的工具、用户或外部来源归属。核心重查断言、来源和适用范围；目标已变时，材料可以正常提炼，但不能直接验证新主张或解除新版 held。

只确认本次适用条件时使用 recall 重评，不持久化结果或提高 assessment。模型互审可以发现漏项，但 helpful、召回次数和代理复述都不增加外部证据。

## 从召回到使用：经验状态与本次适用性分开

state/basis/assessment 记录经验的使用状态和依据，applicability 描述经验本身的边界。本次条件是否成立由 taskApplicability 表示，只放在请求结果里。切换项目不会因此修改 Experience 或 revision。

| 层面 | 值与用途 | 不代表什么 |
|---|---|---|
| 经验状态 | active/held/disabled，沿用准入和复评 | active 不代表本次就适用 |
| 经验边界 | general/conditional/unknown，保存在记录中 | 持久 unknown 不等于只缺当前上下文 |
| 本次适用性 | applicable/not_applicable/undetermined，由当前信息计算 | 不把一次不适用写成全局错误 |
| 返回用途 usage | guidance/lead，分别为可采用经验/待核实线索 | lead 不把低依据假设变成可执行规则 |

guidance 和 lead 都先检查授权、active、准入组合、有效期、当前修订、来源、依赖和未确认写屏障。held、disabled、过期、撤回、争议、无权限或持久 applicability=unknown 的内容均不得进入自动返回。browse/inspect 可以按权限查看可见记录，但查看权限不等于自动使用资格。

资格通过后，先判断与任务是否相关，再检查所有条件和例外。必要条件明确不成立，或任一例外成立，就返回 not_applicable；另有未知条件也不能改成线索。条件全部成立且例外均已排除时，才是 applicable/guidance。

没有明确冲突、只是缺少当前可核实信息时，结果为 undetermined。只有高度相关且能列出具体 missingChecks 的记录才返回 lead。general 同样要与任务相关，并符合当前指令。

线索要说清为什么相关、结论受什么条件限制、还缺哪些条件或例外，以及要核实的问题。它用于决定下一步查什么，不携带可直接执行的命令。没有具体可回答的问题，就不返回 lead。

消费端先使用已有真实上下文，需要补查时仍受当前任务权限和预算约束。API 的线索开关、核实轮次、定向刷新及失败处理统一见[召回与核实合同](04-contracts-and-extensions.md#核实后定向重评)。检查困难不会使经验进入 held，也不能把未确定结果改为可采用。

## 核实结果的两条去向

| 实际发现 | 当次使用 | 是否修改经验 |
|---|---|---|
| 当前对象满足已知条件 | 更新 context 后定向重评，返回 guidance 才可采用 | 不改 state/revision/assessment，不增加独立支持 |
| 当前对象不满足条件或命中已有例外 | 本次不采用 | 保留原经验，不自动停用或删除 |
| 仍缺信息或检查失败 | 保留未确定并停止本轮检查 | 不把查询困难记成经验错误，不自动保存新候选 |
| 发现主张的新增支持、遗漏条件或新反例 | 将真实材料作为 claim 补证回传 | 核心按准入和复评决定保持、修订、held 或确认错误后 disabled |
| 用户明确要求删除 | 停止使用并按用户范围执行 | 走现有删除流程；Agent 的不适用结论本身不是删除授权 |

一次检查可能同时获得当前条件与主张的新证据，两类结果分别处理。“项目 B 的文件由工具生成”只确认文件性质，不能证明所有生成器行为相同。提交与重评的具体参数见[核心操作](04-contracts-and-extensions.md#核心操作)。

跨项目不等于跨知识集合：消费方可在项目 B 使用已授权通用集合内、未限定项目 A 的经验。若 B 的新材料属于另一个 scope，只能在那里形成新材料/经验，不能用 verificationFor 把私有证据自动带进通用集合；扩大范围按显式发布与脱敏规则处理。

指导结果只对响应组装时的上下文成立，已经送入代理上下文的文本无法远程收回；消费端须按接口合同刷新后再采用。

## 暂缓、复评与停止使用

未通过准入的 proposal 留在短期 LearningJob，不形成永久候选库。模型或服务失败要单独报告，不能当作“内容没有价值”。具体清理期限见[材料与派生产物保留](07-storage-model.md#材料与派生产物保留)。

已有经验出现实质冲突、来源或父经验失效、范围不清时，可以进入 held。新增假设只有在用途明确、有具体核实问题且用户明确要求保留时，才可进入 held。

每条 held 必须填写 review.reason、question 和 reviewBy。默认期限见[复评字段约束](07-storage-model.md#准入与复评字段约束)。新证据、用户澄清、来源修订或依赖恢复可以触发复评；定时重试、再次召回和同源重复输入不延长期限。

| 转换 | 条件与结果 |
|---|---|
| proposal → active | 价值与证据门槛通过，字段/来源/范围有效 |
| proposal → held | 仅显式保留的有用途假设，并有复评问题与期限 |
| active → held | 与该结论有关的实质冲突/来源变化，先阻断建议再登记复评 |
| held → active | 有新有效材料解决缺口，完整重跑准入；不靠等待时间或模型信心 |
| held → disabled | reviewBy 到期仍未解决；停止自动复评，说明原因，不制造新状态 |
| active/held → disabled | 用户明确停用，或已确认错误；停止使用，不删除其来源历史事实 |
| disabled → active/held | 用户显式重新开启或请求复评，重新校验；普通 Connector 重放不重新启用 |

reviewBy 到期或补证引发状态修改时，都使用同一写者及 expectedRevision；到期任务若发现目标已补证为新修订，必须重读，不能误停新版本。新材料可触发复评，但在同一轮 unresolved 等待中不自动延长 reviewBy；用户显式请求新的复评周期才可重设。

reviewBy 限定本次等待核实的时间，validUntil 限定经验的有效期。有效期一到就停止召回，无需等待后台改状态；这不表示结论过去就是错的。held 到期转 disabled 后仍可查看。首版不会因为长期未使用而删除低频经验，也不会反复催用户审批，删除按用户的保留配置执行。

经验可能随环境变化失效，因此不设置“永久正确”状态。即便证据真实，也仍要判断后续价值。评测分别统计噪声、重要经验覆盖和任务收益，不能靠全部收下或全部拒绝来通过。

## 来源与历史的最小规则

evidence 保留连续原文、真实归属、支持或反驳关系及服务生成的来源指纹。位置、作者和时间只填写实际存在的信息；模型不得创造这些信息。字段、指纹算法和摘录容量统一见[Evidence 合同](07-storage-model.md#evidence-与来源指纹)。

指纹用于定位来源副本和判断失效，不代表事件身份或独立支持次数。不同 Connector 对象即使文字相同也保留不同来源归属；同源转载不能自动增加可信程度。普通来源更新使旧版本支持失效，不等同用户永久忘记，新版本可以重新提炼。

Connector 用 source_binding 定位对象的 current/pending 修订及片段指纹。用户要求忘记整个源对象时，绑定被排除，未来修订也不自动接收。未识别的外部转载不在自动清理承诺内。

已知转载或同一来源由扩展在批次中标明共同归属；不明来源独立性时不增加支持。首版不提供自动可信度累计分数，也不承诺识别所有语义抄录。

纯派生经验可以没有直接 evidence，但必须引用有效父经验并继承根来源。来源超出记录预算时须缩小主张或暂缓产出，不能丢弃来源后继续发布；摘录也不能删掉限定词后沿用原判定。

首版保存当前经验、revision 和必要来源，历史正文与回滚不在首版范围。derivedFrom 绑定引用修订，用于发现父经验已变化；引用修订的原文不可用时如实显示，不能用当前文本冒充。材料、未完成写操作及引擎副本的保留边界见数据模型。

## 提取与整理

流程按工作内容组织，轮次结束或空闲仅是扩展的提交时机。核心不以“任务已成功”判断是否允许学习。

1. 校验材料范围、大小、来源归属，脱敏后才持久化。超限输入返回可处理的错误；扩展按主题分片，保留分片覆盖信息。
2. 提取生成零条或多条候选，拆分意图与事实，保留条件、例外、归属、期限和层次；不只寻找用户纠正。适配器可复用引擎原生提取，再映射为领域 proposal，按准入表判断持续性和后续价值。
3. 服务执行结构与来源校验；只把必要邻居交给整理步骤，分别判断重复、补充、冲突和泛化。模型可建议合并，不能直接删除或改变范围。
4. 按 admissionDecision 逐条执行 reject/merge/retain_active/retain_held；服务核对允许的状态组合，reject 留短期原因，held 必须带有限复评计划。
5. 变更经验进入限定主题的整理队列，检索相关案例并寻找反例；符合条件时形成新的推导经验。

每份材料默认只运行一次基础提取；复用引擎原生提取时，领域层不重复执行同一流程。高层推断、冲突或高风险主题可以增加审查，再用独立标注评估收益是否抵得上成本。模型复核用于查漏纠错，不算新的外部证据。

| 关系 | 处理规则 |
|---|---|
| 完全重复 | 相同范围、主张、条件、例外及来源内容不新增；不同提交重试不增加支持 |
| 语义重复 | 比较完整条件与归属后保留一个主张；来源确实独立才可追加 |
| 互补 | 只有不改变原主张含义的补充可并入；更新后重新检查依据 |
| 条件差异 | 通常并存，或明确拆分范围；不能强行求一个泛化句子 |
| 冲突 | 先区分本人要求与客观断言；外部建议不推翻本人偏好。相同对象/条件下的实质事实矛盾才 contested/held，不按多数票决定 |
| 纠正 | 本人明确改变偏好/有权设定的约束可修订；事实纠正仍核验依据。当前任务例外不改写长期规则，日期较新不自动更真实 |
| 泛化 | 新建经验、绑定实际支持修订；保留原案例；主动检索反例，没有反例也不证明不存在 |

整理只处理变化项及索引找到的有限邻居。首期每项最多读取 20 个邻居，执行一次模型整理；超出预算的工作延后，未读取部分不计入覆盖范围。跨案例实验至少区分两个独立案例和一个检验边界的案例。这个样本安排用于试验，不意味着两例就足以证明规律。

## 派生、纠正和删除

`derivedFrom` 只引用真正用于推导的其他经验修订，不表示“上一版”。首版禁止同经验自支持和修订图循环；根来源的重复不能因为经过多次推导而变成新支持。再次召回产生的代理复述可作为使用记录，不能作为独立观察。

父经验修订、停用、删除或出现冲突后，子经验须重新评估才能继续作为建议。查询时递归检查引用版本是否仍为当前、可用且有权限；预算不足则暂不返回。后台逐步更新依赖或撤回结论，详见[故障与一致性](03-architecture.md)。

停用保留经验与来源供查看，不再用于建议；编辑递增当前修订；删除清除当前经验及其索引。删除来源摘录时，先阻断引用它的经验及派生建议，再清理当前复制位置和作业材料，并按剩余证据重新提炼。异步清理须区分“已停止使用”和“清理完成”。

来源链接失效不自动等于经验错误：已有摘录仍可显示，但明确原件不可访问。来源被纠正、替代或撤回则必须重新检查主张。Connector 的临时不可访问、权威删除和用户忘记分别处理；部分拉取失败不证明来源已删除。

核心保留必要的无正文删除记录。有关任务可能重放或产品管理备份仍含相关材料时不清除；恢复须先应用当前删除和停用意图，否则进入维护与重新导入流程。持久字段见[管理记录合同](07-storage-model.md#管理记录的最小合同)，恢复步骤见[架构](03-architecture.md)。产品不能从外部复制备份中远程抹除数据。
