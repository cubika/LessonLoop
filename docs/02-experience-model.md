# 经验模型与学习规则

日期：2026-09-13。本文定义学习语义；字段形状、容量和全部持久化对象以[存储数据模型](07-storage-model.md)为准，组件映射见[架构](03-architecture.md)。

## 三个概念

Material 是代理适配、Connector 或用户提交的有限材料，包含原文、归属和必要上下文。它是学习输入，不是必须永久保留的事件。Experience 是可独立解释和修订的经验。LearningJob 是处理输入的后台任务，其身份不参与经验有效性或用户检索。

来源摘录作为经验的一部分保存，来源可以没有系统原生 ID。经验 `id` 和一个 `revision` 用于编辑、停用、引用及过时结果排除。作业身份仅用于处理进度与恢复，可选来源位置用于查看原件。

## 抽象层次

| 层次 | 回答的问题 | 成立条件与示例 |
|---|---|---|
| L1 事实经验 | 观察或明确陈述了什么 | “这次生成步骤覆盖了手工修改。”引用输出或当事人陈述，并区分两者 |
| L2 关联经验 | 哪些现象在观察中一起变化 | “这些样本中，扫描数据增加时延迟也增加。”写明样本范围；不宣称因果 |
| L3 因果解释 | 什么机制可能解释结果 | “执行计划显示未利用分区裁剪，额外扫描增加耗时。”证据须支持机制；排除不了替代解释则仍是假设 |
| L4 条件模式 | 什么条件下会重复出现 | 比较案例后提出“生成产物的手工变更会在再生成时丢失”，限定确实被覆盖的生成方式和例外 |
| L5 原则或模型 | 什么能迁移到其他决策 | “改变生成结果前先找到生成源”，保留机制、适用限制和迁移验证范围 |

L1–L5 是分类，不是五级晋升。L1 可以比 L5 更可靠；高层级没有默认排序奖励。用户直接提交 L5 时无需编造低层事实。自动推导也不要求每层各产出一条，输出零条是有效结果。

L2 的共同变化、L3 的机制解释、L4 的跨案例模式要分别评测。一次操作成功不证明唯一原因；多次转载不证明模式重复发生；更换具体名词不构成有效迁移。

## 最小经验记录

字段由模型提出或由服务设置，职责必须分开。模型返回的对象只是 proposal，不能直接成为存储状态。

| 字段 | 语义与设置者 | 使用方式 |
|---|---|---|
| `id`, `revision` | Mem0 生成稳定 ID；服务递增修订号，从 1 开始 | 更新、引用、旧索引排除；只有一个领域修订号 |
| `scopeId` | 服务依据调用身份选择的知识归属集合 | 强制授权过滤；独立于 repo/branch 等适用条件 |
| `applicability` | general / conditional / unknown | 持久规则边界；unknown 不进入默认指导或线索，与当次缺上下文分开 |
| `conclusion` | 单一可复用结论；提炼器提出 | 展示、语义检索与字段查询 |
| `level` | L1–L5 | 分类和可选筛选；不决定可信程度 |
| `purpose` | fact / constraint / lesson / procedure / rationale，单值 | 按用户用途浏览，与抽象层次独立 |
| `conditions`, `exceptions` | `{text, match?}` 数组；match 为受控 key+values | 条件 AND，例外 OR；据本次上下文计算适用/不适用/未确定 |
| `topics`, `entities` | 主题与有意义的精确名称，均可为空 | 多维索引；大小写敏感标识符保留原样 |
| `basis` | reported / observed / inferred，服务依据材料归属设定 | 说明结论来自陈述、直接观察还是推断 |
| `assessment` | attributed / supported / hypothesis / contested | 产品策略设置；记录当前证据边界，不是概率 |
| `evidence` | 少量连续原文短摘录、归属与可选位置 | 详情核查，默认不嵌入、不注入自动上下文 |
| `sourceFingerprints` | 直接及派生根来源指纹的并集 | 服务生成，来源清理与重复定位；不计独立支持次数 |
| `derivedFrom` | 其他经验 `{id, revision}` 列表，可为空，限同 scope | 推导解释与失效检查；不复制父经验全文 |
| `state` | active / held / disabled | 可用、暂不建议、已停用；由服务或用户控制 |
| `review` | held 时必填的原因、待核实问题与 reviewBy | 有限复评计划，默认 30 天结束本次等待，不是执行授权 |
| `createdAt`, `updatedAt`, `validFrom`, `validUntil` | 写入时间与可选有效区间 | 时间过滤；观察发生时间留在 evidence |

`supported` 只表示在记录的条件下有相应依据，不是执行保证或普遍正确。`reported` 表示有人陈述，`observed` 表示直接观察，`inferred` 表示推导；三者都不自动等于可靠。用户说过某句话只证明其陈述存在，不能据此确认客观事实。

general 需要确认当前没有额外任务限制，不能只因条件留空就设置。conditional 可以只有例外；L5 仍可能 conditional。采集所在 repo/branch 首先是来源上下文，只有结论依赖它们才提炼为条件。

`active` 仅表示通过下文准入规则，使用时还须检查授权、适用性和有效期。用户纠正的“已接收”“旧建议已暂停”“新规则已生效”是服务回执事实，不新增经验状态，细节以[接口与回执](04-contracts-and-extensions.md)为准。`held` 用于已保存经验的暂停或用户明确选择保留的少量待验证假设，不接收所有不确定 proposal。`disabled` 表示已停用；删除另走清理流程。用户确认可以确定其本人偏好或有权设置的要求，不能替代事实或因果证据。

为了保持每条结论可单独修订，一条经验只保存一个主要主张。需要相互独立的事实和流程时分开存；不要建立逐句证明 DSL。任何领域字段改变都产生新 revision，包括层次、用途、主题、实体、依据和判定；创建时间保持不变，更新时间随修订变化。技术性重建索引或作业 nonce 变化不改变 revision。

## 准入：先判断是否该记，再判断能否用

每次提取先拆开消息中的独立主张，判断持续意图、内容性质、适用范围与价值。当前任务要求仍由宿主执行，但不因为执行过就进入长期记忆。关键词只是线索；转述、引用、条件句、后一句的例外都必须一起理解。

| 输入及例子 | 判定依据 | 持久化与使用结果 |
|---|---|---|
| 一次性要求：“这次先用 npm” | 明确限定当前任务，无后续用途 | 不创建 Experience；不覆盖已存 pnpm 规则，当前任务由宿主处理例外 |
| 有期限的跨任务约定：“本周试点都用 X” | 真实用户、明确期限和后续用途 | 经价值检查可 active；存 validUntil/明确可判断的终止条件，到期停止召回 |
| 持续偏好：“以后我的总结尽量简短” | 真实本人在表达偏好，适用对象明确 | purpose=constraint，reported + attributed；可 active，不需要实验验证喜好 |
| 有权设置的要求：“这个项目统一用 pnpm” | 确认是制定要求而非描述事实，且调用身份可设置该范围 | purpose=constraint，reported + attributed；可 active，保留例外与范围 |
| 事实：“项目现在使用 pnpm”或“接口最多 100 条” | 是对客观情况的描述，需要当前配置、正式资料或相关观察支持 | 不因用户自信就激活；支持充分为 supported/active，否则提取保留在短期作业 |
| 原因：“这次失败肯定是缓存” | 原话是解释，证据是否支持该机制并区分替代解释 | 不直接激活；保留有依据的观察，原因作为 hypothesis proposal |
| 原则或流程：“超时就重试一定安全” | 检查前提、副作用、反例及支持范围 | 不能因表述通用或标成 L5 激活；证据与适用范围均足够才 supported/active |
| “记住这个结论”但结论未验证 | 明确保存意图，不代表事实确认 | 仅在用途明确且有具体复评问题时建立 held；否则说明未形成可用经验 |

`purpose=constraint` 专指真实用户为本人或有权管理范围设定的规范，包括本人偏好。“某文档规定如此”是外部事实陈述或流程，应使用 fact/procedure 等用途并检查适用权威，不能仅靠命令句式取得 constraint。用户没有权利替其他人设置偏好，也不能把“这更快”改写成“我偏好它”来绕过事实核验。混合句子可以分为本人选择和独立事实判断两条。

持续性不明确时默认不升为长期规则。只有会影响重要后续行为的歧义才请求一次简短澄清，不要求用户逐条审批。明确的限期跨任务规则可保存，单次任务要求不能仅靠设置到期时间变成值得长期存的经验；“直到迁移结束”等边界若不可判断，不能默认为永久有效。

用户明确表达的本人偏好，在指定范围内不因外部模板或建议相反而进入 held。用户后来改变偏好则按真实新意图修订；来源撤回、本人纠正或适用范围不明仍会触发复评。事实矛盾按证据处理，不能因作者是用户就保持为真。

## 价值筛选与可执行判定

准入分别执行以下检查，不能用单一模型分数相互抵消。后续用途、新增价值与范围完整性是所有新增经验的门槛；证据充分性进一步决定可以 active，还是仅允许显式保留为 held：

1. 后续用途明确：能说明何种未来任务会少做调查、少犯相同错误，或需要遵守何种持续约定。一次少见但代价大的发现也可通过，不要求先重复多次。
2. 内容有新增价值：不是进度、普通完成、无新增信息的重复或既有规则改写。同源多次输入不增加价值或独立支持。
3. 主张与范围完整：一个主要结论，保留会改变行动的条件/例外，能在预算内完整表达；抽象不得扩大证据覆盖。
4. 证据支持到哪一步：本人偏好依据本人原话，事实依据相应资料或观察，推导依据机制与案例。充分为 pass，尚无法确认或排除为 unknown，已否定/来源伪造为 fail；“很有用”不能使 unknown/fail 变成 pass。

提取作业保留一份短期 admissionDecision：内容性质、持续性、后续用途一句话、各检查结果、处置与简短原因。不保存模型长推理或长期评分。处置为 reject/merge/retain_active/retain_held；没有通过价值筛选的内容直接 reject，不放进 held 等待用户清理。模型可以提出判定，服务验证来源、类型、范围、有效期和状态组合后才写入。

新增 retain_active 要求 supportAdequate=pass。新增 retain_held 仅允许 supportAdequate=unknown，且后续用途、新增价值与范围完整性通过、有真实用户的明确保留意图及 review 计划。supportAdequate=fail 的新主张不因“记住”进入 held；可以另提炼有依据的纠错发现。既有经验出现相互冲突的材料时可暂入 held 重新核对，已经确认错误则 disabled。

active 的允许组合只有两类：已通过上述检查的 supported 经验；或真实本人偏好/有权设置的规范性要求，purpose=constraint、basis=reported、assessment=attributed，并有明确对应的可信用户摘录。外部 attributed 事实、hypothesis 和 contested 都不能作为已确认指导自动使用。scope 权限、applicability 和来源有效性仍在每次召回时检查。

## 怎么验证

| 验证对象 | 最低应检查的证据 | 不能据此声称什么 |
|---|---|---|
| 原文与归属 | 摘录确实来自实际材料，角色由可信通道决定 | 引文真实不证明内容真实 |
| 偏好/规范性要求 | 用户确实在表达意图，有权设定该范围，期限及例外完整 | 不证明配套的性能/因果解释 |
| 客观事实 | 对象/版本一致的配置、正式资料或实际观察，与断言直接相关 | 一次观察不证明任何环境都成立 |
| 方法/流程 | 实际前提、步骤与结果，覆盖会影响结论的例外 | 测试成功不等于全场景保证 |
| 因果解释 | 机制证据，或有区分力的比较/干预；明确尚未排除的其他解释 | 先后发生、重复成功或模型共识不等于唯一原因 |
| 跨案例模式/原则 | 独立案例、共同条件、反例检索及未参与提炼任务的迁移表现 | L5 标签、记录数量不等于经过迁移验证 |

核心先检查已经提交且获准使用的材料，不为验证自动联网或执行命令。缺少信息时输出具体待核实问题，由宿主在当前任务授权范围内决定是否读取配置、查询资料或运行测试；没有授权则不执行。review.question 是数据，不是可执行指令或权限授予。

针对经验主张的新增结果通过 submitMaterial 的 verificationFor 绑定同 scope、已授权的目标 ID 与 revision，仍保留真实工具/用户/外部归属。本次适用条件的确认只走 recall 重评，不自动持久化或提高 assessment。核心重新校验断言、来源和适用范围；目标已变时可按普通材料提炼，但不能自动验证新主张或解除新修订 held。模型互审可以帮助发现漏项，但不增加外部证据；helpful、被召回次数、代理重复转述也不会自动提高 assessment。

## 从召回到使用：经验状态与本次适用性分开

持久 state/basis/assessment 表示这条经验是否获准保留与使用、依据是什么；applicability 表示经验本身有没有明确边界。本次 taskApplicability 表示这些条件在当前任务是否成立，仅存在于请求结果，不写入 Experience，也不因项目切换而改 revision。

| 层面 | 值与用途 | 不代表什么 |
|---|---|---|
| 经验状态 | active/held/disabled，沿用准入和复评 | active 不代表本次就适用 |
| 经验边界 | general/conditional/unknown，保存在记录中 | 持久 unknown 不等于只缺当前上下文 |
| 本次适用性 | applicable/not_applicable/undetermined，由当前信息计算 | 不把一次不适用写成全局错误 |
| 返回用途 usage | guidance/lead，分别为可采用经验/待核实线索 | lead 不把低依据假设变成可执行规则 |

两种返回用途先通过同一资格门槛：授权范围、active、准入合法组合、有效期、当前修订、来源与依赖有效、无未确认写屏障。held、disabled、过期、撤回、争议、无权限及持久 applicability=unknown 不得以 lead 绕过。显式 browse/inspect 仍可按既有权限查看可见记录，但不进入自动线索。

资格通过后判断任务目标是否相关，再检查全部条件和例外。已知必要条件不成立或任一例外成立，结果为 not_applicable；即使同时有未知条件也不返回线索。条件均成立且例外均排除为 applicable/guidance。没有明确冲突，仅缺少当前可核实信息时为 undetermined；只有高度相关且能列出具体 missingChecks 的项才可 lead。general 也必须与任务相关并符合当前指令，不能当作总是需要注入。

线索明确说明相关性、经验的条件化结论、尚缺的条件或例外及核实问题，不携带要直接执行的操作指令。只返回“可能有用”却没有可回答问题，不满足 lead 门槛。默认 API 不启用线索；只有声明理解用途并实际实现先检查后采用的消费端显式开启。支持该协议的官方 Copilot plugin 开启线索，旧客户端仅收到 guidance。

Agent 在原任务已有权限内核实，优先复用刚读过的上下文和低成本检查。单个任务针对同一经验最多两轮检查，必须有新信息；重复 recall、重排缺口或服务重启不能伪造新证据。无权限、工具失败、没有增量或预算耗尽时停止，该项仍未确定，不能自动采用，也不因此创建 held。

## 核实结果的两条去向

| 实际发现 | 当次使用 | 是否修改经验 |
|---|---|---|
| 当前对象满足已知条件 | 更新 context 后定向重评，返回 guidance 才可采用 | 不改 state/revision/assessment，不增加独立支持 |
| 当前对象不满足条件或命中已有例外 | 本次不采用 | 保留原经验，不自动停用或删除 |
| 仍缺信息或检查失败 | 保留未确定并停止本轮检查 | 不把查询困难记成经验错误，不自动保存新候选 |
| 发现主张的新增支持、遗漏条件或新反例 | 将真实材料作为 claim 补证回传 | 核心按准入和复评决定保持、修订、held 或确认错误后 disabled |
| 用户明确要求删除 | 停止使用并按用户范围执行 | 走现有删除流程；Agent 的不适用结论本身不是删除授权 |

任务适用性重评复用 recall(target={id,revision}, context)，不调用 verificationFor。经验主张补证复用 submitMaterial(verificationFor={id,revision}, ...)，保留真实材料并按同 scope 及授权规则处理。一次检查同时涉及两层时分别发出：不能拿“项目 B 是生成文件”证明“所有生成器都有相同行为”。模型置信度、操作成功或 helpful 也不能代替主张验证。

定向重评先复核当前自动资格，包括权限、active/合法依据、有效期、来源/依赖和写屏障；任一不通过统一 target_unavailable，不泄露隐藏内容。资格通过后才比较修订，已变为 target_changed，旧 missingChecks 不应用于新版。repo、branch、目标对象、版本或任务约束改变时，消费端丢弃此前当次判定并重新检查。

跨项目不等于跨知识集合：消费方可在项目 B 使用已授权通用集合内、未限定项目 A 的经验。若 B 的新材料属于另一个 scope，只能在那里形成新材料/经验，不能用 verificationFor 把私有证据自动带进通用集合；扩大范围按显式发布与脱敏规则处理。

指导结果是基于组装时上下文的判断，不是永久执行许可。核心保证每次返回时复核当前状态，消费端在依赖经验开展新动作前按适配合同刷新状态；已经交给代理的文本无法远程收回。

## 暂缓、复评与停止使用

未获准入的 proposal 只留在短期 LearningJob，正常完成后 7 天清理相关内容，不创建永久“候选经验”。模型/服务失败与内容未通过是不同原因，不得把前者报告为内容没价值。

held 仅用于：已保存经验发生实质冲突、来源/父经验失效或范围不清；以及用户明确保留、用途明确且有具体验证问题的假设。每条 held 必须有 review.reason、question 和 reviewBy；默认从本次进入 held 起 30 天。新证据、用户澄清、源修订或依赖恢复触发有限复评；单纯定时重试、重新召回和相同来源重复输入不延长期限。

| 转换 | 条件与结果 |
|---|---|
| proposal → active | 价值与证据门槛通过，字段/来源/范围有效 |
| proposal → held | 仅显式保留的有用途假设，并有复评问题与期限 |
| active → held | 与该结论有关的实质冲突/来源变化，先阻断建议再登记复评 |
| held → active | 有新有效材料解决缺口，完整重跑准入；不靠等待时间或模型信心 |
| held → disabled | reviewBy 到期仍未解决；停止自动复评，说明原因，不制造新状态 |
| active/held → disabled | 用户明确停用，或已确认错误；停止使用，不删除其来源历史事实 |
| disabled → active/held | 用户显式重新开启或请求复评，重新校验；普通 Connector 重放不重新启用 |

reviewBy 到期或补证引发状态修改时，都使用同一写者及 expectedRevision；到期任务若发现目标已补证为新修订，必须重读，不能误停新版本。新材料可触发复评，但在同一轮 unresolved 等待中不自动延长 reviewBy；用户显式请求新的复评周期才可重设。

reviewBy 是本次等待期限，validUntil 是经验的有效期，不能互相代替。有效期届满即停止召回，不必等后台改状态；到期不意味着结论曾经是错的。held 到期转 disabled 保留用户可检查的内容，首版不以未使用自动删除低频但重要经验，也不反复推荐其审批；实际删除遵守用户保留配置。

不设置一个“永久确认正确”的状态。已有依据不代表永久有效，证据真实也不代表有未来价值；提取噪声、重要经验覆盖和后续任务收益分别评测，质量目标不是全收或全拒。

## 来源与历史的最小规则

每个 evidence 项保留 `excerpt`、`role`（user / agent / external / tool）、`relation`（supports / contradicts）与服务计算的 `fingerprint`。可选 `locator`、`author`、`observedAt` 只填写实际存在的信息。提取 proposal 用输入片段下标引用材料；服务检查摘录确实来自该片段，再写入 evidence。模型不得创造链接、作者、时间或原文。

fingerprint 在材料持久化前由服务计算：正文先脱敏、Unicode NFC 规范化、换行统一 LF，保留大小写及其余空白。手动材料按 scopeId+完整片段正文的 UTF-8 长度分隔编码计算 SHA-256；Connector 材料增加服务确定的 bindingId、sourceRevision、partKey，区分来源及其版本，详细规则见[持续同步](08-connectors.md)。

指纹按完整片段生成，不按短摘录生成；经验与作业沿用同一指纹。派生继承根指纹，不重新对摘要计算。Connector 原生对象 ID、版本和游标只保存在同步管理状态。

指纹用于定位来源副本和判断失效，不代表事件身份或独立支持次数。不同 Connector 对象即使文字相同也保留不同来源归属；同源转载不能自动增加可信程度。普通来源更新使旧版本支持失效，不等同用户永久忘记，新版本可以重新提炼。

Connector 用 source_binding 定位对象的 current/pending 修订及片段指纹。用户要求忘记整个源对象时，绑定被排除，未来修订也不自动接收。未识别的外部转载不在自动清理承诺内。

已知转载或同一来源由扩展在批次中标明共同归属；不明来源独立性时不增加支持。首版不提供自动可信度累计分数，也不承诺识别所有语义抄录。

材料全文仅在学习作业中短期保存，完成后默认 7 天清理，确定失败最多 30 天；uncertain 所需材料在修复前保留。经验 evidence 典型为 1–2 条，最多 3 条，每段 excerpt 不超过 512 B，整个 evidence JSON 数组不超过 2 KiB。原文不能机械截断后保留原判定；应重新选取短摘录、缩小主张或暂缓产出。

纯派生经验可以没有直接 evidence，但必须引用有效父经验，evidence 与 derivedFrom 至少一者非空。sourceFingerprints 由服务计算直接和父记录根来源的并集，最多 32 个；超限不能丢弃指纹后继续发布。整条 Experience JSON 最大 16 KiB，检索文本及持久 payload 限额见存储模型；这些是产品预算而非数据库限制。

首版保存当前经验、revision 和必要来源，历史正文与回滚不在首版范围。derivedFrom 绑定引用修订，用于发现父经验已变化；引用修订的原文不可用时如实显示，不能用当前文本冒充。未完成写操作的拟写内容临时保留在同一 Qdrant 管理 collection，修复前不按普通作业清理。

## 提取与整理

流程按工作内容组织，轮次结束或空闲仅是扩展的提交时机。核心不以“任务已成功”判断是否允许学习。

1. 校验材料范围、大小、来源归属，脱敏后才持久化。超限输入返回可处理的错误；扩展按主题分片，保留分片覆盖信息。
2. 一次领域提取生成零条或多条 proposal，拆分意图与事实，保留条件、例外、归属、期限和层次；不只寻找用户纠正。随后按准入表判断持续性和后续价值。
3. 服务执行结构与来源校验；只把必要邻居交给整理步骤，分别判断重复、补充、冲突和泛化。模型可建议合并，不能直接删除或改变范围。
4. 按 admissionDecision 逐条执行 reject/merge/retain_active/retain_held；服务核对允许的状态组合，reject 留短期原因，held 必须带有限复评计划。
5. 变更经验进入限定主题的整理队列，检索相关案例并寻找反例；符合条件时形成新的推导经验。

默认一次提取，没有强制第二模型审判。对高层推断、冲突处理或高风险主题可配置额外审查，并用独立标注决定其成本是否值得。模型复核是质量检查，不能变成新的外部证据。

| 关系 | 处理规则 |
|---|---|
| 完全重复 | 相同范围、主张、条件、例外及来源内容不新增；不同提交重试不增加支持 |
| 语义重复 | 比较完整条件与归属后保留一个主张；来源确实独立才可追加 |
| 互补 | 只有不改变原主张含义的补充可并入；更新后重新检查依据 |
| 条件差异 | 通常并存，或明确拆分范围；不能强行求一个泛化句子 |
| 冲突 | 先区分本人要求与客观断言；外部建议不推翻本人偏好。相同对象/条件下的实质事实矛盾才 contested/held，不按多数票决定 |
| 纠正 | 本人明确改变偏好/有权设定的约束可修订；事实纠正仍核验依据。当前任务例外不改写长期规则，日期较新不自动更真实 |
| 泛化 | 新建经验、绑定实际支持修订；保留原案例；主动检索反例，没有反例也不证明不存在 |

整理只遍历变化项与索引找到的有限邻居，不全库回放。首期每项最多 20 个邻居、一次模型整理；超出预算延后，不能把未看过的范围说成已覆盖。跨案例提炼至少区分两个独立案例与一个用于检验边界的案例；这是首期实验设计，不是“两例就证明规律”的准入定理。

## 派生、纠正和删除

`derivedFrom` 只引用真正用于推导的其他经验修订，不表示“上一版”。首版禁止同经验自支持和修订图循环；根来源的重复不能因为经过多次推导而变成新支持。再次召回产生的代理复述可作为使用记录，不能作为独立观察。

如果父经验修订、停用、删除或出现冲突，子经验在重新评估前不能继续作为建议。查询时递归验证引用修订仍为当前、可用且在授权范围内；预算不足就暂不返回。后台逐步重评，更新依赖或撤回结论。详见[故障与一致性](03-architecture.md)。

停用保留经验与来源供查看，不再用于建议；编辑递增当前修订；删除清除当前经验及其索引。删除来源摘录时，先阻断引用它的经验及派生建议，再清理当前复制位置和作业材料，并按剩余证据重新提炼。异步清理须区分“已停止使用”和“清理完成”。

来源链接失效不自动等于经验错误：已有摘录仍可显示，但明确原件不可访问。来源被纠正、替代或撤回则必须重新检查主张。Connector 的临时不可访问、权威删除和用户忘记分别处理；部分拉取失败不证明来源已删除。

Qdrant 管理 collection 保留必要的无正文删除记录：经验 ID 或 scopeId+fingerprint、删除时间。有关任务可能重放或产品管理备份仍含相关材料时不清除。首版不承诺任意旧快照自动恢复；恢复须保留并应用当前删除记录，否则进入维护与明确审查的重新导入流程。不建立单独控制数据库，也不承诺从外部复制备份中远程抹除数据。
