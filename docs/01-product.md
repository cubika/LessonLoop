# 产品定义

日期：2026-09-14。状态：待实施的产品设计。术语与字段以[经验模型](02-experience-model.md)为准；发布方式以[安装设计](10-distribution-and-installation.md)为准。

## 产品要完成的工作

把值得复用的工作经验留下来，在下一次真正相关的任务中提供帮助，并在条件变化后及时修订。衡量结果的是少做重复调查、少纠正相同错误、少维护知识；存储数量和高层经验比例不是学习效果。

产品同时控制无用内容的留存和重要经验的遗漏。只保存更少内容可以降低噪声，却也可能漏学；让用户逐条审核则把提炼工作交还给用户。两者分别评测，不用一个指标替代另一个。

经验的范围可以跨仓库、跨项目或跨工作场景。知识集合决定哪些调用方可以读取，适用条件决定何时应使用；repo、branch 只是可选条件，采集时所在位置不自动变成限制。

初期面向一个人在多个项目中使用代理、阅读资料和积累工作经验的场景。先提供本地运行、单用户服务，不引入团队授权、跨设备同步或组织治理。这里的项目可以是代码仓库，也可以是工作主题；核心没有 repository 专用范围。

## 用户任务与体验

| 用户任务 | 产品行为 | 用户可见结果 |
|---|---|---|
| 正常工作时发现值得复用的做法 | 代理适配提交相关材料，后台选择和提炼 | 少量完整经验；没有价值时可以不生成 |
| 持续积累外部资料中的经验 | Connector 同步新增、变更与撤回，核心提炼或校验经验草稿 | 不必反复手动导入，同步与学习进度分别可见 |
| 新任务需要过去的经验 | 按任务语义、实体和授权集合检索，再检查当前条件 | 可采用经验直接供参考；缺少当前条件时返回少量待核实线索，明确要检查什么 |
| 想理解经验为什么这样写 | 展开经验及推导关系 | 原始摘录、归属、观察与推断的区别 |
| 发现当前任务不适用 | 本次不采用，不改全局经验；必要时检查是否发现新的例外 | 其他适用任务仍可使用，无需重新教一遍 |
| 发现经验本身过时或错误 | 提交真实新依据，核心复评；支持直接停用和明确删除 | 受影响建议暂停或修订，派生经验重新检查 |
| 想整理某个主题 | 用主题、用途、层级、时间筛选 | 可浏览的经验集合，冲突和缺证据的内容单独显示 |

默认操作路径是工作、收到相关经验、必要时纠正。新任务开始时自动召回，在规划/行动前提供少量结果；采用相关经验前定向刷新，关键新信息或目标变化时按需补召回。普通工具调用不反复搜索，模型主动 MCP 调用作为补充。高级筛选和来源查看用于排查与整理，不要求用户日常维护分类。支持线索的代理只在原任务授权内核实具体缺口；确认适用后再采用。无需每条经验重新测试，也不为记忆验证自动扩大权限。自动提炼可由用户一次配置启用，并设置材料范围、模型服务和预算。不会要求每条经验批准。

用户界面以经验列表、详情和学习作业状态为主。经验呈现为可用、暂不作为建议、已停用；提取中、模型额度不足、需要修复属于作业状态。不要把存储修订号、作业 nonce、证据哈希或后台重试次数放入普通流程。

日常使用只执行当前任务，按需核实线索，并利用真实反馈改进经验。三组对照是开发阶段的发布前验证，不属于默认产品流程；不会为了实验自动复制用户任务或重复产生外部操作。未来在线实验须另有明确授权及成本设置。

## 产品交付形式

首版包含 CLI 和本地 Web UI，共用一个本地后台服务。Windows 用户通过一条 `irm` 命令安装固定版本，安装器管理核心、记忆引擎和私有运行依赖，用户无需从源码启动或手工部署数据库、Docker。关闭页面或安装终端不影响后台学习；登录自启可选，默认关闭。独立桌面应用和云端控制台不在首期范围。

| 交付物 | 用户用途 | 首版范围 |
|---|---|---|
| PowerShell 安装器与发行组件包 | 一次安装本地服务、CLI、Web UI 与私有运行依赖 | 固定 tag/版本、下载校验、用户目录安装、分项诊断、升级回滚与卸载；程序与数据分离 |
| CLI | 初始化、服务管理、材料提交、检索、详情、修订、停用、删除、导出和诊断 | 日常操作支持结构化输出；异常写入修复有专用管理流程 |
| 本地 Web UI | 查看和管理经验，了解学习状态 | 搜索/筛选、详情与来源、编辑/停用/删除、手动提交、导出、作业状态、模型、集合及 Connector 连接管理 |
| Copilot CLI plugin | 在 Copilot 工作中自动提交材料和使用经验 | 随产品提供，由 setup/agent 命令注册；hooks、MCP、bridge 使用稳定入口，卸载接入保留经验 |
| Connector 接入模块 | 将外部资料与经验持续同步 | 通用运行模块、连接管理和样例 Connector；真实来源实现逐个交付 |
| 客户端 SDK 与 API 文档 | 为其他程序和扩展提供调用方式 | 薄 TypeScript 客户端；通过核心服务访问，普通用户无需单独操作 |

MCP bridge 随代理接入组件交付。首版提供通用 Connector 接入和管理，P4 再逐步增加真实来源。发布采用固定版本 PowerShell bootstrap 与 GitHub Release 平台组件包，默认 Windows x64、普通用户权限；安装器及正式地址尚待实现和发布。

记忆服务和数据本地运行，模型使用已有 Copilot 登录和订阅，不要求独立模型 API key 或付费记忆平台。模型未登录时显示学习待配置，不能把程序安装成功说成全部可用。首次设置确定采集范围；安装不自动导入全部历史。组件、路径、登录、停止和更新行为见[发布与安装](10-distribution-and-installation.md)。

UI 首页直接展示可查询的经验和近期学习状态。经验详情显示用途、依据判定、有效期与暂停原因；暂缓项说明缺什么和复评截止时间。用户纠正的回执由服务事实驱动：可靠接收后反馈“已收到”；明确旧目标已被阻止投递后反馈“旧建议已暂停”；新修订写入确认并具备正常召回资格后才反馈“已生效”。快速完成合并一次最终确认，耗时则更新同一进行中状态；失败、缺证据或目标不明说明原因。收到 jobId 不等于已记住。选择经验后可查看条件、例外和按需展开的来源；错误或待修复任务给出清楚原因。服务级修复不提供无校验的“强制成功”按钮，仍走核心管理流程。UI 与 CLI 的修改、删除、范围权限使用同一套合同，不各自维护状态。

## 何种内容值得留下

| 材料 | 处理 |
|---|---|
| 明确且持续有效的偏好、约束 | 保留实际范围；通常不需要跨案例证明 |
| 调查发现、有效步骤及其适用条件 | 提炼结论，保留观察依据和限制 |
| 失败与恢复过程 | 提取观察；原因证据不足时只记录假设 |
| 多次出现的相关现象 | 比较条件、反例和来源独立性，提出有边界的模式 |
| 用户直接提供的原则 | 可提出 L5 草稿，不补造低层证据；明确采用为本人规范与陈述其客观正确性分别判断 |
| 一次性的安排、进度、普通完成消息 | 默认不作长期经验；扩展可以管理自己的短期任务数据 |
| 没有新增信息的重复、已有经验的复述 | 不新增卡片，不提高可信程度 |

一次发现也可能很有价值，不能要求重复出现才保留。正确的普通完成消息通常没有长期价值；有用的猜测也不能因此当作事实。一次性指令留在当前任务，持续偏好、有权设置的要求与客观断言按[准入规则](02-experience-model.md)分别处理。

准入分别检查后续用途、内容新增性、范围完整性与证据支持；不通过的 proposal 留短期原因。held 只保存被暂停的既有经验和用户明确保留的少量待验证假设，具有复评问题和期限，默认 30 天未解决后停用。用户不承担逐条审核候选的日常工作。

## 首版范围

首版要能提交材料、提炼经验、通过可替换 MemoryEngine 查询，并完成修订与停用。目标首选 Hindsight 自托管，现有 Mem0/Qdrant 原型保留对照；新引擎和发行依赖须单独验收。五层经验既要能表达，也要用一个限定主题的跨案例整理测试实际推导；仅有 `level` 字段不算完成多层学习。

| 必须交付 | 边界 |
|---|---|
| 通用材料 API 和手动提交入口 | 无需 Copilot、仓库或完整会话也能使用 |
| 自动提炼与无结果输出 | 不强制每次提交产生经验；独立评测漏学与噪声 |
| L1–L5 与可解释推导 | 允许直接输入任意层；自动高层提炼先限定主题与预算 |
| 自然语言查询与字段筛选 | 语义、精确标识符、例外查询、范围和时间过滤 |
| 线索核实与反馈 | 有效经验缺当前条件时可返回线索；核实当前任务与修订经验主张分别处理 |
| 去重、补充、冲突与纠错 | 不强行合并冲突；修订后旧建议不可继续送出 |
| Copilot 首个适配 | 自动材料摄入、任务召回、自然语言纠正；宿主能力单独验收 |
| 基本查看、导出、停用和删除 | 能知道保存了什么，哪里失败，如何修正 |
| 准入与有限复评 | 临时指令不长期保存；事实核验与用户偏好分开；held 有退出规则 |

[Connector 持续同步](08-connectors.md)是通用接入能力：用户选择来源、目标集合与频率，系统持续读取新增和变化，核心统一提炼。邮件、文档目录、笔记或工单系统只是可选实现，具体外部协议不进入经验模型。首版用可复现样例验证通用合同，不表示所有来源已经可用。

暂不做：通用代理运行时、完整会话查看器、自动技能执行、Playbook 评定、自动联网补证、全量事件审计、自建通用知识图谱数据库、自动训练模型权重、多用户协作。引擎内部可以使用图索引。对经验的离线评测属于开发工具，不成为用户必须启用的产品子系统。

## 一个贯穿实现的例子

Copilot 调查客户端变更时发现：该项目的客户端文件由 schema 生成，直接修改会被生成步骤覆盖。核心收到有来源的材料后，留下“变更客户端契约时修改 schema 并重新生成客户端”，同时限定项目、路径和生成流程。

下一次用户要求修改接口，代理还不知道目标是否自动生成。若经验有有效依据、与任务相关且没有明确条件冲突，可以返回线索：“当前未确认文件来源，可先核实生成标记和配置。”插件仅在原任务权限内读取必要信息，再携带新上下文重评。确认是生成产物后返回可采用经验；确认手写则本次不用，不能删除原经验。

可迁移的经验进入用户明确授权的通用集合后，也能帮助另一个项目。项目专属规则仍保留项目限制，不能通过线索跨越权限或适用边界。核实若发现一种先前遗漏的生成方式例外，提交新依据走核心修订；用户停用或来源撤回后，任何路径都不能再把它包装为线索自动送出。

Connector 可持续提交工作材料或现成经验草稿，核心使用相同模型提炼、校验与检索。例如文档更新后重评相关经验，邮件转发不算多次独立观察；来源类型不决定经验可信程度。

## 成功与失败

首版验收要分别知道：重要经验有没有学到、留下的内容是否有用、条件是否完整、后续任务是否正确取回、使用后是否减少重复工作。无法建立来源的原因推断、错误范围的建议和撤回后继续出现的内容都是失败。

产品允许少量重要内容因来源矛盾暂缓使用，允许模型或索引异常时明确返回不可用。它不允许用“没有匹配”掩盖后台失败，也不允许为凑满结果而扩大授权范围。[实施与验收](05-delivery-and-validation.md)给出冻结样本和判定方法。
