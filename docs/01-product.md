# 产品定义

日期：2026-09-14。状态：待实施的产品设计。术语与字段以[经验模型](02-experience-model.md)为准；发布方式以[安装设计](10-distribution-and-installation.md)为准。

## 产品要完成的工作

让一次调查或纠正能帮助后续工作，是 LessonLoop 的主要用途。经验要在相关任务中被取回，条件变化后也要及时修订。产品效果看用户是否少做重复调查、少纠正相同错误，以及维护经验要花多少时间。记录数量和高层经验比例不能代替这些结果。

噪声和漏学要分别评测。少存内容可能让结果看起来更准确，也可能漏掉重要发现。提炼应由产品完成，用户不必逐条审核。

经验可以跨仓库、项目和工作场景使用。知识集合决定谁能读，适用条件决定何时有用。repo、branch 是可选条件；一条经验在某个分支被发现，并不意味着它只适用于那个分支。

首期服务于个人：在多个项目中使用代理，阅读资料并积累工作经验。产品本地运行，提供单用户服务；团队授权、跨设备同步和组织治理不在首期范围。项目可以是代码仓库，也可以是工作主题，核心不设置 repository 专用范围。

## 一个贯穿实现的例子

Copilot 调查客户端变更时发现：该项目的客户端文件由 schema 生成，直接修改会被生成步骤覆盖。核心收到有来源的材料后，留下“变更客户端契约时修改 schema 并重新生成客户端”，同时限定项目、路径和生成流程。

下一次用户要求修改接口，代理还不知道目标是否自动生成。若经验有有效依据、与任务相关且没有明确条件冲突，可以返回线索：“当前未确认文件来源，可先核实生成标记和配置。”插件仅在原任务权限内读取必要信息，再携带新上下文重评。确认是生成产物后返回可采用经验；确认手写则本次不用，不能删除原经验。

可迁移的经验进入用户明确授权的通用集合后，也能帮助另一个项目。项目专属规则仍保留项目限制，不能通过线索跨越权限或适用边界。核实若发现一种先前遗漏的生成方式例外，提交新依据走核心修订；用户停用或来源撤回后，任何路径都不能再把它包装为线索自动送出。

Connector 可持续提交工作材料或现成经验草稿，核心使用相同模型提炼、校验与检索。例如文档更新后重评相关经验，邮件转发不算多次独立观察；来源类型不决定经验可信程度。

## 用户任务与体验

| 用户任务 | 产品行为 | 用户可见结果 |
|---|---|---|
| 正常工作时发现值得复用的做法 | 代理适配提交相关材料，后台选择和提炼 | 少量完整经验；没有价值时可以不生成 |
| 持续积累外部资料中的经验 | Connector 同步新增、变更与撤回，核心提炼或校验经验草稿 | 不必反复手动导入，同步与学习进度分别可见 |
| 新任务需要过去的经验 | 按任务语义、实体和授权集合检索，再检查当前条件 | 可采用经验直接供参考；缺少当前条件时返回少量待核实线索，明确要检查什么 |
| 想理解经验为什么这样写 | 展开经验及推导关系 | 原始摘录、归属、观察与推断的区别 |
| 发现当前任务不适用 | 本次不采用，不改全局经验；必要时检查是否发现新的例外 | 其他适用任务仍可使用，无需重新教一遍 |
| 发现经验本身过时或错误 | 提交真实新依据，核心复评；支持直接停用和明确删除 | 受影响建议暂停或修订，派生经验重新检查 |
| 想整理某个主题 | 用主题、用途、层级、时间筛选 | 可浏览的经验集合，冲突和缺证据的内容单独显示 |

用户照常工作，系统在新任务的规划或行动前自动召回少量经验。采用前刷新相关条目，得到影响判断的新信息或任务目标变化时，再补充召回。普通工具调用不会反复触发搜索，模型也可以主动调用 MCP 深入查询。

待核实线索只用于回答具体缺口。代理在原任务权限内检查，确认适用后才采用；已有充分信息的经验无需重复测试。用户一次配置材料范围、模型服务和预算即可启用自动提炼，日常不必逐条审批或维护分类。高级筛选和来源查看留给需要排查、整理的时候。

界面主要显示经验列表、详情和学习进度。经验状态用“可用”“暂不作为建议”“已停用”表达；“提取中”“模型额度不足”“需要修复”显示在作业上。修订号、nonce、证据哈希和后台重试次数只用于诊断，不进入普通操作流程。

日常任务只执行一次，必要时核实线索，并用真实结果改进经验。三组对照由开发者在发布前单独运行，不能在后台复制用户任务或重复外部操作。以后如需在线实验，必须另行明确授权和成本设置。

## 产品交付形式

首版计划提供 CLI、本地 Web UI 和共享后台服务，首个工作代理适配为 Copilot。模型使用现有 Copilot 登录和订阅；记忆服务与数据本地运行，推理仍通过 Copilot 云端进行。当前没有可用安装包。

| 交付物 | 用户用途 |
|---|---|
| Windows 安装包 | 安装、启动与管理本地组件，升级保留配置与经验 |
| CLI 与 Web UI | 提交、查询、查看依据、纠正、停用、删除与导出，了解学习进度 |
| Copilot 插件 | 自动提交工作材料，在新任务中使用经验并跟踪纠正结果 |
| ConnectorRuntime 与样例 Connector | 配置外部资料同步；真实来源实现后逐项公布 |
| 客户端 SDK 与 API 文档 | 供程序与其他代理接入同一服务 |

关闭页面或安装终端后后台继续学习；登录自启可选。首次设置确定材料范围，安装不自动导入全部历史。安装、登录、升级及卸载细节见[发布与本地运行](10-distribution-and-installation.md)。

用户提交纠正后，界面按实际进度显示已收到、旧建议已暂停或新规则已生效。失败、缺依据或目标不明时说明原因，不能只因提交成功就说已经记住。UI 和 CLI 使用相同的修改与授权规则，接口细节见[纠正回执](04-contracts-and-extensions.md#纠正回执与展示时机)。

## 何种内容值得留下

| 材料 | 处理 |
|---|---|
| 明确且持续有效的偏好、约束 | 保留实际范围；通常不需要跨案例证明 |
| 调查发现、有效步骤及其适用条件 | 提炼结论，保留观察依据和限制 |
| 失败与恢复过程 | 提取观察；原因证据不足时只记录假设 |
| 多次出现的相关现象 | 比较条件、反例和来源独立性，提出有边界的模式 |
| 用户直接提供的原则 | 可提出 L5 草稿，不补造低层证据；明确采用为本人规范与陈述其客观正确性分别判断 |
| 一次性的安排、进度、普通完成消息 | 默认不作长期经验；扩展可以管理自己的短期任务数据 |
| 没有新增信息的重复、已有经验的复述 | 不新增卡片，不提高可信程度 |

一次发现也可能值得保存，尤其是代价高、难以再次查明的问题。普通完成消息即使正确，通常也没有长期价值；猜测即使有启发，也不能当成事实。一时的指令留在当前任务，持续偏好、用户有权设置的要求和客观断言分别按[准入规则](02-experience-model.md)处理。

未达到保留条件的内容不进入经验库。暂缓的经验说明缺什么以及复评期限；没有新依据时按期结束等待。详细准入与状态见[经验规则](02-experience-model.md)。

## 首版范围

首版要能提交材料、提炼经验、通过可替换 MemoryEngine 查询，并完成修订与停用。目标选择 Hindsight 自托管，Mem0/Qdrant 已退出实现范围；引擎和发行依赖须单独验收。五层经验既要能表达，也要用一个限定主题的跨案例整理测试实际推导；仅有 `level` 字段不算完成多层学习。

| 必须交付 | 边界 |
|---|---|
| 通用材料 API 和手动提交入口 | 无需 Copilot、仓库或完整会话也能使用 |
| 自动提炼与无结果输出 | 不强制每次提交产生经验；独立评测漏学与噪声 |
| L1–L5 与可解释推导 | 允许直接输入任意层；自动高层提炼先限定主题与预算 |
| 自然语言查询与字段筛选 | 语义、精确标识符、例外查询、范围和时间过滤 |
| 线索核实与反馈 | 有效经验缺当前条件时可返回线索；核实当前任务与修订经验主张分别处理 |
| 去重、补充、冲突与纠错 | 不强行合并冲突；修订后旧建议不可继续送出 |
| Copilot 首个适配 | 自动材料摄入、任务召回、自然语言纠正；宿主能力单独验收 |
| 基本查看、导出、停用和删除 | 能知道保存了什么，哪里失败，如何修正 |
| 准入与有限复评 | 临时指令不长期保存；事实核验与用户偏好分开；held 有退出规则 |

[Connector](08-connectors.md)持续读取指定来源的新增和变化。用户设置目标集合与频率，核心负责提炼；邮件、文档目录、笔记和工单系统各自实现来源协议。首版用可复现样例验证接入合同，真实来源的支持情况逐项公布。

暂不做：通用代理运行时、完整会话查看器、自动技能执行、Playbook 评定、自动联网补证、全量事件审计、自建通用知识图谱数据库、自动训练模型权重、多用户协作。引擎内部可以使用图索引。对经验的离线评测属于开发工具，不成为用户必须启用的产品子系统。

## 成功与失败

验收分别检查漏学、留存价值、条件完整性和后续召回，再看是否减少重复工作。原因推断没有依据、建议用错范围、撤回后仍继续投递，都应判为失败。

来源有矛盾时可以暂停相关经验，模型或索引异常时应报不可用。后台失败不能显示成“没有匹配”，返回条目不足也不能扩大授权范围。测试样本和判定方法见[实施与验收](05-delivery-and-validation.md)。
