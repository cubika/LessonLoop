# 产品定义

日期：2026-09-15。状态：当前产品设计，已有部分实现；实现与验收进度见[13](13-implementation-plan.md)。

## 产品目标

LessonLoop 帮助个人和工作 Agent 从真实工作中持续学习做事方法。系统整理调查、尝试、决策和结果，比较相关经历，形成排查流程、决策规则和工作清单；下次工作时使用这些方法，再根据新结果调整它们。

产品主线是：工作经历 → 自动复盘与经验提炼 → 方法库 → 任务使用 → 方法改进。用户积累的是一套逐渐适合自身工作的做法，可以查看、指定使用、纠正和导出。

用户管理三类内容：Source 保存来源片段，Experience 表达可复用经验，Playbook 提供任务做法。工作过程与使用效果在详情中按需展开；用户无需维护单独的工作案例或效果案例。检索后一次返回完整条件、步骤与检查，Agent 执行并判断，后台记录结果和复盘。

首期面向在多个项目中使用 Agent 的个人，从代码调查和修改场景开始，先完成一个工作主题的完整流程。方法按问题和工作主题组织，项目、工具、版本是适用条件。产品本地运行；材料提炼使用现有 Copilot 订阅，推理仍经过云端。

## 用户功能

| 功能 | 触发与处理 | 用户得到什么 |
|---|---|---|
| 自动复盘 | 工作出现阶段结果、结束或收到补充材料时，整理关键尝试与结果 | 可核对的工作案例，包含有效做法、无效尝试和未解决的问题 |
| 经验提炼 | 从真实观察中提炼有后续用途、依据和明确范围的主张，按需比较相关案例 | 可直接复用的局部规则，或支撑方法的经验 |
| 方法库 | 将经验组织成步骤、分支、完成检查和停止条件 | 能理解、修改和复用的做法，而非越来越长的聊天记录 |
| 主动使用 | 新任务推荐相关方法；用户也可显式指定 | 与本次情况匹配的步骤，遇到未知条件先检查或停在决策点 |
| 方法进化 | 新结果带来遗漏条件、反例或更好的步骤顺序 | 有来源的具体修订；普通重复成功不制造新版本 |
| 效果回顾 | 用户开启后汇总方法变化、使用依据、问题和额外成本 | 可查看的 good/bad case 和周期回顾，不把工具调用次数算成收益 |

## 一个贯穿实现的例子

某次客户端修改在重新生成后丢失，修改 schema 再生成则保留了结果。另一任务发现 legacy 目录是手写代码。这些经历形成一个方法：先识别文件的维护来源，再决定修改生成源还是直接修改文件，最后检查正常生成流程后的结果。

方法在第一步检查生成标记和配置。结果确定后才选择分支；未确定时不猜。后来一个案例说明某生成器的扩展区允许手工代码，方法便增加有版本和路径限制的分支。原来有效的生成与手写路径仍保留。

需要判断其他派生产物时，可结合配置编译等经历提炼“改变派生产物前先识别其权威来源”的原则，并据新任务修正适用范围。这个例子说明目标体验，不代表已完成运行。

## 经验的形成与范围

经验有后续用途、充分依据和明确范围后，本次学习即可结束；一次发现也可以直接支撑局部方法。只有扩大范围、解释冲突或处理反例需要时，才继续比较案例或分析原因。没有新增价值时可零产出。

L1–L5 保留为研究与质量诊断的可选分析视角，不参与发布资格或日常流程。用户主要阅读方法目标、步骤和变化，追问时可展开经验及来源。具体定义见[学习模型](02-experience-model.md)。

## 官方工具与产品分工

以 Hindsight 自托管和官方 Agent 集成为复用起点。官方已有事实与因果关系提取、observations 归纳、reflect、mental models、UI、CLI 和使用日志。LessonLoop 使用这些能力，组织完整的方法形成、使用与演进体验，能力依据见[官方复用核查](research/2026-09-14-agent-integration-reuse/README.md)。

官方 Agent 集成中的事件、采集、回填和诊断代码优先复用；产品方法调用由 AgentAdapter 接到 LessonLoop。官方插件直连 Hindsight 的流程用于隔离基线，不能仅改地址就当作产品接入。

工作案例、产品经验、方法版本和用户控制由 LessonLoop 持有，Hindsight 是 MemoryEngine 的首个实现。替换引擎需要适配、数据迁移和验收，用户方法的产品语义保持不变。UI 和 CLI 是操作入口，不能仅凭提供这些入口宣称新增价值。

## 首版范围

首版包含限定主题的工作案例整理、有依据的经验提炼、方法生成与更新、方法库 UI/CLI、Copilot CLI 主动使用、样例 Connector、可选效果回顾，以及 Markdown、清单和 Skill 快照导出。支持统一 Windows 安装和后台运行，阶段安排见[实施与验收](05-delivery-and-validation.md)。

首版不提供通用工作流执行器、自动安装或更新宿主 Skill、多用户协作、跨设备同步、模型权重训练或生产任务自动 A/B。方法指导工作 Agent，执行仍由宿主决定；导出 Skill 是可审阅文件，不自动授予工具权限。

## 用户设置与控制

工作学习、方法自动推荐、效果回顾和通知分别保存设置，页面可以单独调整。安装 CLI 的学习开关会同时调整学习和推荐，具体行为见[安装说明](14-alpha-release.md#管理)。开启学习时选择来源范围、历史导入范围、模型和预算；安装不会自动导入全部历史。静音只停止通知，关闭效果回顾不停止独立开启的学习，关闭学习不删除既有方法。

普通复盘与合格方法更新在已授权范围内自动进行，无需逐条审批。用户可查看依据、编辑、停用、删除和导出。明确纠正显示可靠接收、旧版暂停与新版生效的实际状态。新材料不能覆盖用户设置的持续要求。

## 成果与评价

产品成果是形成能指导任务的方法、在新任务中合理使用，以及新经历改变了具体做法。进一步观察无效尝试、重复调查、完成质量和维护成本。方法数量、最高层级或模型自评分不能代替这些结果。

首先完成一个主题的完整体验，再以合理配置的官方方案作为主要增量对照。评测属于开发与发布工作，不成为用户日常使用的前提。方法库体验见[12](12-method-library.md)，工程决策见[06](06-review-and-decisions.md)。
