## 第一阶段交付范围

交付单用户、本机运行的 LessonLoop：从获准工作材料整理案例，提炼有用途、依据和范围的经验，形成和更新方法，经方法库 UI/CLI 查看、管理和导出，并在 Copilot CLI 的新任务中准备和使用方法。后台学习、方法自动推荐、效果回顾及通知分别设置。

阶段内包含样例 Connector、效果回顾和 Windows 安装、后台、升级与卸载。“可选回顾”表示用户可选择开启，功能仍须交付。P4 的更多真实来源、其他宿主、第二种 MemoryEngine、多用户及 Skill 自动安装同步不在本阶段范围。

当前没有需要保留的旧用户数据，首版从当前格式初始化。旧开发 bank 布局、旧原型和未发行版本的数据转换不列入待办；保留当前格式的备份恢复、兼容检查及用户控制。方法用于较晚未见任务的迁移能力仍须验收。

核心、学习与方法管理、宿主适配、样例 Connector、效果回顾和运行管理已有代码。工程测试、真实模型案例和发行验收分别记录；先读下方当前进度，再按工作包定位剩余工作。

## 复用优先的实现方式

官方能力依据见[复用核查](research/2026-09-14-agent-integration-reuse/README.md)。源码核查固定在该记录的提交；W01 另固定实际可运行、可分发的组件版本。每项实现先用官方能力验证相应场景，再补具体缺口。

| 能力 | 首选实现 | LessonLoop 增量 |
|---|---|---|
| 存储与基础 API | 官方文档、facts/observations、来源、bank/tag、索引和 SDK | 保存产品对象、稳定身份、授权、修订及控制；不复制原生图、向量或提取存储 |
| 原生后台处理 | 官方持久作业、查询、取消、重试和清理 | LearningJob 关联原生操作，记录产品阶段、取消意图及发布结果；不另造底层任务执行器 |
| 经验形成 | retain/observations mission 与官方提取、归纳 | 工作案例组织、按需比较与解释、来源独立性与准入检查 |
| 方法生成和更新 | 隔离原生作业生成候选并审查，Mental Model保存当前正文 | 方法Schema、结构/依据/路径检查；直接提交已检查的候选，读回后发布 |
| 检索与方法使用 | 官方检索、标签过滤和候选读取 | 当前发布资格、版本与依赖核对，preparePlaybook 的完整指导与反馈关联 |
| UI/CLI | 官方适合的内容、编辑组件与SDK | 接到产品API，提供方法视图、当前变更说明、任务准备、控制回执及导出 |
| Copilot 接入与模型 | 官方 hooks、会话读取/写回、上下文注入、安装诊断和 Copilot provider | 产品调用转换、真实任务边界、完整方法投递、结果关联与范围检查；先补官方模块接线 |
| 使用记录 | 官方usage/diag中含义相符的记录 | task_feedback直接保存投递、任务结果和用户评价，供效果回顾和通知读取 |

官方专用 Copilot 插件和统一 coding-agents 包均已有采集与回填能力，触发时机及覆盖按选定版本核对。页面复用官方适合的管理组件，负责方法操作和任务关联；多轮执行留在 Copilot，不另建页面执行器。

Hindsight 通过隔离作业生成候选并保存当前正式方法正文；ProductStore 只保存依据引用、修订标记、发布状态和用户控制。方法通过结构、依据及路径审查后写入，正文读回与投影确认后才生效。当前实现没有切换到同一长期模型的 delta 生成；正式方法 bank 禁止原生入口绕过审查刷新。直接原生调用只用于隔离基线或维护；复用 UI 组件时也要转换其读写路径。

PublishedProjection 已使用官方独立bank和chunks索引，前置资格过滤及中文查询有局部实测，完整检索质量仍按05/09验收。来源或方法停用的产品屏障始终存在。原生来源重处理会重置curation，Mental Model的新写入检测也不能替代来源删除后的即时失效处理。

官方配置、输出 Schema、薄适配即可满足的功能，按配置和适配交付。新增引擎代码、长期维护的上游补丁或额外索引，要记录触发它的失败场景、改动范围和对应验收；不按模块名称预先重写官方能力。

2. 新任务的维护来源未知时，一次获取完整方法；Agent从诊断步骤开始，取得观察后在生成文件和手写文件路径中选择。
3. 新材料说明特定版本允许扩展区手工代码，方法新增有限分支，保留原先有效部分；重复成功没有新信息时不改产品版本。
4. 用户纠正、来源撤回、原生重处理及重启后，旧建议不再投递；新版本未确认时明确保持暂停。
5. 在较晚未见任务中使用修订后的方法，查看当前变更说明与实际结果，并从最终 Windows 安装包重复完整路径。

学习器只接收获准正文、真实角色和上下文。预期答案、审阅说明、判定标签和未来迁移任务信息不进入提炼；留出学习材料不用于调参，仅在冻结配置后的验收运行中输入。已有材料须经适配与独立判定后才能成为验收场景。

## 实现中的决策与故障处理

| 决策点 | 首选与需要核实的结果 | 不成立时的处理 |
|---|---|---|
| 原生方法生成 | 隔离作业的mission与Reflect/Mental Model Schema能表达目标方法，并给出可核对来源 | 先调整配置和Schema；仍失败才调整方法组装，记录具体失败场景 |
| 原生作业与发布衔接 | 可靠取得操作身份、阶段、取消及终态，产品发布另行确认 | 保留 uncertain 和屏障，先查原操作；不盲重放或把原生 completed 当产品生效 |
| 发布投影 | 原生命名空间可前置过滤资格，写后读回与产品版本对应 | 增加可重建投影；保留官方学习索引，不重做提取 |
| 原生 UI 复用 | 组件可通过产品 API 读取、修改及显示回执，原生入口隔离 | 只补必要产品页面或组件，不为复用界面开放控制旁路 |
| 原文与长期依据 | 产品和原生副本能按 07 清理，当前方法仍有获准的长期支持 | 暂停不合格方法，调整明确的保留配置或管线；不暗留全文 |
| Windows 默认组合 | 固定数据库扩展、引擎、provider 和本地模型组件可按 10 打包运行 | 继续不依赖该问题的实现，记录阻塞；需要改变产品支持范围时先形成具体可审阅方案 |

日常技术选择在已确定范围内推进。P0 的未验证项用于控制依赖和判断实现方式，不要求每通过一个关卡重新申请开工。产品范围或关键合同若需改变，先同步相应主文档和影响说明。
