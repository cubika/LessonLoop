## 实测发现

Mem0 3.1.8 的发布包在导入时直接引用未用的 better-sqlite3 和 pg。没有 SQL 包时，尚未构造 Qdrant 配置就导入失败。P0 用严格 loader 拒绝这两个 provider 的实际使用，保留 Mem0 与 Qdrant 算法原样。无 SQLite 数据文件的检查通过，但这不是原始 npm 包开箱即用的结果，发布前需要修正包加载边界。

Qdrant JS client 1.19.0 移除 Mem0 调用的 search 方法，实际搜索报错；固定到 1.18.0 后通过。Qdrant server 为 1.19.1。本地嵌入使用固定版本 MiniLM q8、384 维，只验证英文小样本，不代表中文质量。

CLI 1.0.83 实际在首次模型请求前应用 userPromptSubmitted.modifiedPrompt 和 userPromptTransformed 的变更。前者与读取到的当前官方说明不同，报告保留了差异；实现须绑定已测版本，不能只按网站说明猜测行为。

preToolUse 明确 deny 阻止了测试目录的 view 读取；hook 超时则继续执行读取，postToolUse 收到实际文件结果，后续脚本模型请求也包含该结果。因而不能靠 hook 超时建立“记忆服务不可用就一定停止工具”的保证。采用前刷新仍须有显式失败处理与真实 Agent 配合验收。

全部宿主协议试验仅用 loopback 脚本响应，5 次请求、0 次真实模型调用，没有 Copilot 账号凭据。它证明时序接口可以工作，不证明 Agent 会正确采用经验，也没有测试异步纠正回执 UI。
